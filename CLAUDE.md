# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Accio Launcher is a PyQt6 desktop launcher for Harry Potter PC games (Windows 10/11). All UI text and code comments are in **French**. Targets Python 3.12+ (`build.bat` prefers 3.14, falls back to 3.13 then 3.12). PyQt6 ≥ 6.11 / PyInstaller ≥ 6.16 support Python 3.14 (verified 2026-06-12).

**Linux support is a stated future goal** : gate every win32-specific call behind `sys.platform == "win32"` with a sensible fallback (see `self_update.can_self_update`, `win_utils`, `system_checks`, `game_registry.disponible` for the pattern), prefer cross-platform APIs, and never assume drive letters outside guarded code.

**Le registre sous Linux** : il n'y en a pas — mais le jeu, lui, tournera sous **Wine, qui a le sien**. « Pas de registre » serait donc un contresens : le travail n'est pas à supprimer, il est à rebrancher sur `wine regedit` (ou une écriture directe dans `system.reg`). Tout passe déjà par `game_registry.disponible()`, un seul point : aujourd'hui il rend False hors Windows, la fiche n'affiche aucun sélecteur de langue (annoncer un réglage qu'on ne sait pas appliquer est un mensonge) et le lancement ne journalise aucun échec. Le jour venu, c'est cette fonction et `_ecrire_eleve` qui changent, rien d'autre.

## Architecture

Two layers under `src/`, glued by an orchestrator (`game_operations`) and a Qt signal bus.

### `src/core/` — business logic, no PyQt widgets except QThread/QObject/pyqtSignal

- `config.py` — `Config` dataclass with atomic JSON save (tmp+rename). `get_documents_dir()` uses Win32 `SHGetFolderPathW` to handle OneDrive / redirected Documents. Bundle paths differ in PyInstaller frozen mode (`sys._MEIPASS`) vs dev. `APP_VERSION` lives here, kept in sync with `pyproject.toml [project] version`.
- `game_data.py` — Frozen dataclasses for the catalog. `load_catalog()` merges embedded `src/data/games.json` with `~/Games/AccioLauncher/catalog_cache.json` — **highest `catalog_version` wins (strictly greater)**. Embedded is the always-available fallback. **`GameData.from_dict` validates `executable` paths at parse time** — refuses `..`, absolute paths, drive letters. **Le catalogue porte ses propres traductions** : bloc `i18n` par jeu (`name`, `description`, `tags`) et par version (`changes`), résolu AU PARSING par `_loc()` — `set_language()` tourne avant `load_catalog()`, donc `game.name` est déjà dans la bonne langue et aucun site d'affichage ne change. Les traductions vivent dans le catalogue et non dans `i18n.py` parce que **le catalogue se met à jour à distance, indépendamment des releases** : un jeu ajouté doit pouvoir arriver traduit sans republier l'exe. `_loc` refuse une valeur qui changerait le TYPE du champ (catalogue trafiqué). **Le catalogue porte aussi une mise en garde par jeu** : `warning` (traduisible par le bloc `i18n`) et `warning_url` (**https uniquement, validé au parsing** — c'est la seule chaîne du catalogue qui atteigne le navigateur de l'utilisateur ; un refus vide le lien sans emporter l'avertissement). Affichée par `ActionPanel._build_alerts` au DERNIER rang, en NOT_INSTALLED et en INSTALLED — prévenir avant le téléchargement, puis expliquer un jeu qui refuse de démarrer. Née de HP7 partie 2, dont une DLL est mise en quarantaine par les antivirus. Remplissage via **`tools/apply_catalog_i18n.py`** (idempotent, liste les chaînes non traduites) — à rejouer sur le dépôt `accio-launcher-games`.
- `game_manager.py` — Owns `Config`, the catalog, the `GameState` map and les **empreintes SHA-256 des assets** (`set_asset_digests` / `expected_hashes`). `expected_hashes(version)` résout ce qu'il faut vérifier : le catalogue (`sha256` / `sha256_parts`) d'abord — seule option hors GitHub — puis les empreintes **publiées par GitHub** ; (None, []) si rien, la vérification est alors sautée, jamais un échec. La recherche est **insensible à la casse du nom d'asset** (cas réel : catalogue « hp6.7z.001 » vs asset « HP6.7z.001 » — GitHub sert les deux, son API ne publie que la forme canonique) ; une ambiguïté de casse est ignorée plutôt que devinée. Multi-parts : **tout ou rien**, une liste trouée décalerait les empreintes d'un cran. Pre-launch logic delegated to `pre_launch.py`. `refresh_states()` re-detects all states from disk (called after `install_path` changes; preserves transient DOWNLOADING/INSTALLING states). **`_backfill_missing_versions`** (init/refresh/reload) : un jeu détecté INSTALLED sans entrée `installed_versions` reçoit la version recommandée (en mémoire, persistée au prochain save) — sinon `has_update` serait muet à vie. Les MàJ de jeux sont notifiées par **`MainWindow._notify_game_updates`** (recompte LOCAL + toast cliquable, au boot différé et après reload catalogue — le signal `update_counts` du checker ne voit que le catalogue distant). **Langue de jeu** : `detect_game_language` (ce que le registre porte RÉELLEMENT), `game_language` (choix explicite → détection → langue d'interface → première du catalogue), `set_game_language`, `apply_game_language(game, code=None, confirmer=None)` — appliquer AVANT de persister, sinon un UAC refusé laisserait en config un choix que le registre n'a pas pris, et chaque lancement redemanderait l'élévation. `langues_disponibles(game)` filtre sur la PRÉSENCE du fichier témoin (`requires_file`) : le registre ne fait que SÉLECTIONNER une langue, les fichiers viennent du disque d'origine, et proposer une langue absente serait promettre un jeu qui n'existe pas — mesuré : HP7 partie 1 n'embarque que `DH1_French.pck`, la partie 2 les sept. **`valeurs_registre(game, code)`** compose ce qui part réellement dans la clé : les valeurs COMMUNES du bloc (`values`, avec `%INSTALL_DIR%` substitué) **plus** celles de la langue, la langue en dernier car plus spécifique. Une seule écriture pour les deux — même clé, donc une seule invite UAC au lieu de deux à la suite, et deux invites d'affilée sont le meilleur moyen de faire refuser la seconde. `launch_game(game_id, confirmer=…)` transmet le rappel de prévenance jusqu'à `ecrire_valeurs`. Playtime stats: `add_playtime` / `get_playtime` / `last_played` persisted in config; sessions are timed in `MainWindow._on_game_launched/_on_game_exited` (sessions < 10 s ignored), displayed as ONE discreet line in `InfoPanel` (hidden when never played).
- `game_registry.py` — **Lecture/écriture des valeurs de registre d'un jeu** (2026-08-21). Né du besoin réel : HP7 lit sa LANGUE dans le registre, et la langue est une *préférence du joueur*, donc écrite au LANCEMENT d'après un choix par jeu — pas figée après l'extraction. Trois contraintes relevées sur une vraie installation : **vue 32 bits** (`KEY_WOW64_32KEY`, sinon on écrit à côté de ce que lit un jeu 32 bits), **valeurs nommées ET typées** (`Language` en REG_SZ, `1.0\\Language` en REG_DWORD), **HKLM exige l'élévation** — d'où : on lit (gratuit), on compare, et on n'écrit que si ça diffère. L'écriture élevée passe par un `.reg` UTF-16 + `regedit /s`, dans un **dossier temporaire à nom aléatoire** (`mkdtemp`) — un chemin fixe dans `%TEMP%` laissait un programme non privilégié remplacer le fichier avant son import ADMINISTRATEUR — et **on relit derrière pour vérifier** (`regedit /s` est muet, même en échec). `refus_de_cle` / `refus_de_valeur` sont PURES et constituent la seule barrière entre le catalogue distant et le registre. **`ecrire_valeurs(..., confirmer=…)`** appelle le rappel JUSTE AVANT d'écrire, et seulement quand il y a réellement une écriture à faire : on ne modifie pas le registre de quelqu'un sans le lui dire, et sous HKLM ça enchaîne sur une invite UAC — voir Windows demander une autorisation sans savoir pourquoi, c'est la refuser, et le jeu ne démarre pas. Comme le rappel ne se déclenche qu'en cas d'écart réel, prévenir TOUJOURS ne devient jamais un nag : au deuxième lancement personne n'est dérangé. **`disponible()`** dit si ce système a un registre atteignable (`sys.platform == "win32"`) : hors Windows, `game_language` rend None (donc pas de sélecteur affiché — annoncer un réglage qu'on ne sait pas appliquer est un mensonge) et `apply_game_language` rend True sans rien tenter (sinon `launch_game` journaliserait un échec à CHAQUE partie). Le jour du portage Linux, l'écriture par `wine regedit` passera ICI et nulle part ailleurs.

  **Ce que lisent réellement HP7 partie 1 et 2** (relevé le 2026-08-22 dans `hp7.exe` et `hp8.exe`, pas deviné) : la clé `SOFTWARE\Electronic Arts\Harry Potter and the Deathly Hallows Part 1` (resp. `Part 2`) est une chaîne du binaire, et les deux exe lisent **`Locale`** et **`Install Dir`** — **jamais `Language`**, contrairement à ce qu'écrit l'installeur EA. Les valeurs acceptées sont une table posée juste après la chaîne `Locale`, et elles **DIFFÈRENT d'une partie à l'autre** : partie 1 `en_UK fr_FR it de es pl ru`, partie 2 `en fr it de es pl ru`. C'est ce qui explique la contradiction des guides communautaires (« `fr` ») avec le registre d'une vraie machine (« `fr_FR` ») : les deux avaient raison, pour des parties différentes. Le nom de langue (`DH1_French.pck`) et le code du frontend (`fre_fr`) sont dérivés en interne à partir de cet index — d'où `DH1_%s.pck` dans le binaire.
- `pre_launch.py` — Pure functions for UE1 pre-launch (variable substitution, INI patches, file create/delete, DLL unblocking). See "UE1 engine quirks" below.
- `downloader.py` — `QThread` over httpx streaming (**httpx importé paresseusement dans les méthodes des threads** — jamais au top-level, test AST de régression). HTTPS only, multi-part with resume. **Cap on total bytes** = `expected_size_mb × 1.5` (`SIZE_OVERHEAD_FACTOR`). `expected_size_mb=0` disables the cap. **SHA-256 incrémental pendant le stream** (`_download_stream(compute_sha256=True)` retourne le digest — plus d'UI figée à 100 %) ; `_verify_sha256` (relecture intégrale + signal `verifying`) ne sert plus qu'aux parts déjà en cache ; mismatch → delete + retry.
- `self_update.py` — One-click launcher auto-update (Windows frozen only): `.bat` waits for process exit, swaps the exe, relaunches. `can_self_update()` gates it; non-Windows/dev falls back to opening the release page. **`relaunch_after_exit()`** (réutilisé par le bouton « Redémarrer maintenant » et le crash dialog) relance sans remplacer l'exe ; en dev résout `pythonw.exe`. **Le .bat s'écrit avec `newline=""` (sinon `\r\r\n` → cmd coincé dans `:wait`), se lance avec `CREATE_NO_WINDOW` + DEVNULL, JAMAIS `DETACHED_PROCESS` (qui bloque `tasklist | find`), et SURTOUT avec `env=_clean_pyinstaller_env()`** : sans purge des `_PYI_*` (+ `PYINSTALLER_RESET_ENVIRONMENT=1`), l'exe onefile relancé se croit enfant de l'instance morte et crashe « Failed to load Python DLL …\_MEIxxxxxx » — trois pièges Windows reproduits par simulation, voir pyqt-pitfalls #18 et #20.
- `installer.py` — Slim `QThread` orchestrator (extraction → unblock → registry [STUB INACHEVÉ, voir plus bas] → config_files → cleanup). Delegates to `extractors.py` and `post_install.py`.
- `extractors.py` — Pure extraction logic with Zip Slip protection: `extract_7z` (**7z.exe bundlé, unique extracteur 7z** — fine progress, immediate cancellation, native multi-volume `.7z.001` support; **py7zr was fully removed 2026-06-10**), `extract_zip`. Receives progress + cancellation callbacks. Multipart downloads emit the raw `.001` (no concatenation); `Installer._delete_archive` removes all volumes.
- `single_instance.py` (ui) — QLocalServer/QLocalSocket lock; second launch focuses the existing window (`MainWindow.bring_to_front`) and exits.
- `discord_presence.py` — Rich Presence over Discord's local IPC (named pipe / unix socket, **no dependency**). Needs `DISCORD_CLIENT_ID` filled (Discord developer app) or silently no-op. Activity buttons are only visible to OTHER users. Toggle in Settings (`config.discord_presence`).
- `win_taskbar.py` — `TaskbarProgress` (ITaskbarList3 via raw ctypes COM): download/install progress on the Windows taskbar icon. No-op off-Windows.
- `i18n.py` — **FR / EN / ES**, sans dépendance Qt. French strings ARE the keys ; les traductions vivent dans **`src/data/i18n/<code>.json`** (bloc `_meta` + bloc `strings`), plus jamais dans le Python — un traducteur bénévole ne touche aucune ligne de code (guide : `docs/TRANSLATORS.md`). **Ajouter une langue = déposer un fichier** : `available_languages()` le découvre et le sélecteur des Paramètres l'affiche sans changement de code. Repli en cascade **langue → anglais → clé française**, par CHAÎNE, donc une traduction partielle est acceptable. Un fichier dans `~/Games/AccioLauncher/i18n/<code>.json` est **fusionné par-dessus** l'embarqué (test en direct sans release). `set_language(config.langue)` reste appelé à la construction de MainWindow ; changer de langue demande un redémarrage. **Le défaut est l'ANGLAIS** (`config.DEFAULT_LANGUAGE`, aussi le défaut de `Config.langue`) et le premier lancement demande la langue à l'écran 1. **Toute chaîne visible doit passer par `tr()` ET exister dans chaque `<code>.json`** — `tests/test_i18n.py::TestCouverture` extrait les `tr()` par AST et échoue sinon.
- `post_install.py` — `unblock_extracted`, `apply_registry` (**STUB INACHEVÉ, désormais SANS EMPLOI** — ne sait écrire QUE la valeur par défaut d'une clé et redirige HKLM vers HKCU. Le besoin qui le maintenait en vie — l'entrée de registre de HP7 — est couvert depuis le 2026-08-22 par `game_registry` + le bloc `language_registry` du catalogue, qui écrit des valeurs NOMMÉES, typées, en vue 32 bits, avec élévation et relecture. Un bloc `registry` dans `games.json` échoue toujours **en silence** : ne pas en ajouter), `apply_config_files` with `.bak` backup.
- `game_operations` lives in **`src/ui/`** but orchestrates business flows — see UI layer.
- `thread_utils.py` — **`arreter_a_la_fermeture(thread, nom)`**, le geste d'extinction partagé par `GameOperations.cancel_all` et `UpdateDispatcher.shutdown`. En cours de session un thread récalcitrant se GARE (`_zombies`, `shutdown_checker`) ; à la fermeture, non — et le laisser vivant n'est pas neutre : Qt le détruit avec son parent, ce qui **abandonne le processus** (`0xC0000409`, sans message ni rapport de crash, prouvé le 2026-08-21 sur les deux chemins). Attendre davantage est exclu (`read` httpx à 120 s), d'où `terminate()` + `wait()`, borné et sans conséquence quand le processus s'en va aussitôt. Filet : `tests/test_fermeture_threads.py`, en SOUS-PROCESSUS (un abandon emporterait pytest) et qui rejoue aussi l'ancien code en exigeant qu'il plante.
- Smaller helpers: `formatting.py` (size/speed/eta + `format_progress_line` + `format_playtime`/`format_relative_date`), `system_checks.py` (`@functools.cache`d VC++ and DX11 checks, `VCREDIST_URL` — l'URL du correctif vit **à côté** du test qui détecte le manque —, **prérequis PAR JEU déclarés par le catalogue** : `PREREQUIS` mappe un identifiant (`vcredist_x86`, `vcredist2005_x86`, `vcredist2008_x86`) vers (test, page d'aide), et `prerequis_manquants(('vcredist_x86', *game.requires))` est la SOURCE UNIQUE utilisée par `launch_game` ET par le bandeau d'`ActionPanel`. **HP7 partie 1 exige Visual C++ 2005, partie 2 Visual C++ 2008** (Ludo, 2026-08-20) — runtimes distincts du 2015-2022, détectés via l'assembly WinSxS (`crt_x86_present`) et NON le registre (les clés `SideBySide\Winners` n'existent pas sur Windows 11, vérifié). Un identifiant inconnu est ignoré, jamais bloquant : un catalogue en avance ne doit pas verrouiller un launcher plus ancien. `launch_game` lève `RuntimeError('prerequis_manquant:<id>')`, dont `on_play` extrait l'id pour ouvrir la BONNE page, `invalidate_vcredist_cache()` appelé au retour dans la fenêtre après un clic « Installer » [sans ça l'avertissement survivrait à l'installation du paquet], et `needed_space_mb(size_mb)` = ×2 [archive + fichiers extraits], **source unique** partagée par le bandeau d'avertissement et la vérification au clic — deux chiffres différents feraient prévenir d'un blocage qui n'arrive pas), `updater.py` (`UpdateChecker` QThread — catalogue + launcher + **compteurs de téléchargement ET empreintes SHA-256** : `extract_asset_digests` [pure] lit le champ `digest` des assets — **aucune requête de plus**, la réponse est déjà récupérée pour les compteurs — et l'émet via le signal `asset_digests` ; `_check_launcher` fait de même pour l'exe de l'auto-update, dont l'empreinte voyage en 4ᵉ argument de `launcher_update`. Compteurs : `aggregate_download_counts` [pure] fait MAX des parts d'une version puis SOMME des versions ; affiché en pastille `_dl_badge` « ◆ 1 234 téléchargements » à côté de la ligne meta d'InfoPanel [losange U+25C6 comme les séparateurs méta — jamais de flèche ni d'emoji], seuil `_DL_COUNT_MIN`. **Diagnostic réseau** : `network_status(bool)` émis en fin de `run()` — `is_online` ne vaut False que si AUCUN serveur n'a répondu ET qu'au moins une tentative a échoué au TRANSPORT ; une réponse HTTP, fût-elle un 403 de rate limit, prouve la connexion. Un faux « hors ligne » griserait le bouton d'un utilisateur connecté : c'est le seul échec inacceptable ici, d'où les deux garde-fous), `win_utils.py` (`remove_zone_identifier`), `version_utils.py` (numeric `compare_versions`), `self_update.py` (+ `relaunch_after_exit()` réutilisé par crash dialog et bouton Redémarrer).

### `src/ui/` — PyQt6 widgets

- `notification_bar.py` — **Bandeau doré de mise à jour du launcher**, extrait de `main_window` le 2026-08-20. `announce(version, auto=…)` / `set_message` / `set_busy` / `message()`, signaux `download_clicked` et `dismissed`. **Ne s'efface JAMAIS tout seul** (il disparaissait à 30 s : le temps de le lire et d'aller cliquer, il n'était plus là) et la croix écarte la version pour de bon.
- `update_dispatcher.py` — **Cycle de vie des `UpdateChecker` + téléchargement de l'exe d'auto-update**, extrait de `main_window` le 2026-08-20 (1015 → 805 lignes). Règle de partage : **ici, rien qui se voie** — le dispatcher fait tourner des threads et émet des signaux, la fenêtre décide de l'affichage (un `QMessageBox` posé d'ici ramènerait la fenêtre dans le fichier qu'on vient d'en sortir). Porte `_offline_retry` (45 s, ré-armé à chaque échec), `shutdown_checker` (déparentage d'un thread bloqué), `forced_checker()` (retourne le checker SANS le démarrer, pour que l'appelant y branche ses slots de dialogue). **Ne jamais brancher un signal directement sur `manager.set_*`** : `GameManager` a `__slots__` sans `__weakref__`, la connexion lève `SystemError` — passer par un slot du dispatcher (pyqt-pitfalls #46).
- `main_window.py` — Frameless 1200×800 host. Mouse tracking goes through a single `QApplication.installEventFilter(self)` (do **not** add a `MainWindow.mouseMoveEvent` — would only fire on bare surface).
- `game_detail.py` — Per-game detail view (background + transitions + signals). `set_game(g)` is idempotent on same id (refreshes data without replaying the transition). **Owns the single `GameOperations` instance for the whole app.**
- `action_panel.py` — Boutons selon l'état + **bandeau d'avertissement** (`_build_alerts`) affiché UNIQUEMENT en cas de manque : hors ligne (bouton TÉLÉCHARGER grisé), espace disque insuffisant (+ lien « Changer de dossier » → `settings_requested`), Visual C++ x86 absent sur un jeu installé (+ lien « Installer »). **UN SEUL message à la fois**, par ordre de blocage — deux messages empilés coûtaient 80 px et ramenaient la scrollbar à 980×660. **Et un seul message de plus de DEUX lignes coûte exactement la même chose** (mesuré en vraies polices : 33 px pour une ligne, 54 pour deux, 75 pour trois) : le texte du catalogue est donc élidé à `_ALERTE_MAX_LIGNES`, mesuré sur le VRAI QLabel (`heightForWidth`) et non au `QFontMetrics` — le bandeau est en RichText, mis en page par un QTextDocument dont les retours à la ligne diffèrent du texte brut. Pas de pictogramme (Cinzel n'a pas U+26A0 → repli de police Windows, le piège du bouton pause bleu) : un filet ambre `#e8955a` **hors palette de maison** (`themed()` le rendrait vert chez Serpentard). `alert_height()` est lu par `GameDetailView._position_info` pour raccourcir la description d'autant.
- `game_detail_handlers.py` — User action handlers as standalone functions (`on_download(view, …)`, `on_play(view)`, etc.). Keeps `game_detail.py` under 300 lines. Les dialogues **purement informatifs** (« déjà en cours », « espace insuffisant », « sauvegardes conservées ») passent par `view.notify` → toast ; les QUESTIONS et les vraies ERREURS restent des modaux.
- `game_operations.py` — Orchestrator: `download → install`. Single instance → only one operation at a time. Exposes Qt signals (`download_progress`, `install_progress`, `part_info`, `state_changed`, `operation_finished`, `operation_error`, `status_message`) and `is_busy` / `active_game`. `switch_version` **downloads first, uninstalls after** (`uninstall_first` flag) — a failed download must never leave the user with no version. `repair(game)` re-downloads + reinstalls over existing files (context menu « Vérifier / réparer »). Cancel/error paths use `manager.redetect_state`, never a blind NOT_INSTALLED. **Note**: `apply_pre_launch_patches` runs only at launch, not after install — Documents INI files don't exist yet at install time.
- `download_bar.py` — Persistent bottom bar wired to `GameDetailView.ops` so progress survives game switches. `hide_bar()` resets all state to avoid flash on next show. **Stepper « 1/4 · Téléchargement → 2/4 · Vérification → 3/4 · Installation → 4/4 · Finalisation »** piloté par `ops.phase_changed` (`set_phase`) ; pendant « verify » la barre passe en indéterminé (`setRange(0,0)`), re-bornée au prochain progrès.
- `carousel.py` + `carousel_item.py` — Thumbnail strip. **`Carousel.set_games(list[GameData], selected_id=None)` rebuilds items entirely**; per-item state living only on `CarouselItem` is lost on reload. La SURBRILLANCE, elle, est restaurée : `selected_id` sinon `current_game_id()` d'avant la reconstruction, repli sur l'item 0 si le jeu a disparu du catalogue. La méthode reste MUETTE (aucun `game_selected`) — c'est l'appelant qui pose la fiche.
- `video_player.py` + `background_widget.py` — Trailers use **`QVideoSink`** (not `QVideoWidget`), frames painted via `BackgroundWidget.paintEvent` so text/buttons can overlay (`QVideoWidget`'s native surface always renders on top of `QPainter`). `_stop_video()` calls `setSource(QUrl())` to fully release media.
- `info_panel.py` — **Sélecteur de langue dans la LIGNE MÉTA** (`language_clicked`, choix de Ludo le 2026-08-21) : il y tient sans coûter un pixel de hauteur, là où une liste déroulante sous les boutons reprenait ~30 px dans la zone la plus contrainte de la fiche. Affiché UNIQUEMENT pour les jeux qui déclarent `language_registry`. Pas de chevron : Cinzel n'a ni ▾ ni ▼ (vérifié) — le doré fait l'affordance, comme le lien changelog. **Tout ce qui vient du catalogue est `html.escape`é** avant d'entrer dans la ligne méta (RichText) : un `<img src="http://…">` dans un nom de studio déclencherait une requête réseau à l'affichage de la fiche.
- `info_panel.py` / `flow_layout.py` — **anti-troncature** : le panneau est posé en `setGeometry` à 50 % de la fenêtre, donc les largeurs des QLabel `wordWrap` sont rabotées à la place réelle par `_apply_available_width()` (un maximum figé en pixels débordait et le texte était coupé au bord) ; la hauteur des tags est **calculée** par `_relayout_tags()` au lieu d'un plafond fixe qui coupait la dernière ligne. `FlowLayout._do_layout` retombe sur `widget.sizeHint()` quand l'item renvoie (0,0) — `QWidgetItem.sizeHint()` vaut zéro tant que le widget est caché, ce qui est le cas des pastilles pendant le cross-fade et écrasait la hauteur à 0.

### Catalog

`src/data/games.json` (embedded) is bumped together with the remote at `https://raw.githubusercontent.com/ludvdber/accio-launcher-games/main/games.json`. **Keep them in sync** — bad executable paths cause silent launch/uninstall failures.

**Bloc `language_registry`** (HP7a / HP7b) — où un jeu lit ses réglages, et quoi y écrire :

```jsonc
"language_registry": {
  "root": "HKLM", "view": 32,
  "key": "SOFTWARE\\Electronic Arts\\Harry Potter and the Deathly Hallows Part 1",
  "values": { "Install Dir": "%INSTALL_DIR%\\" },   // posé avec TOUTE langue
  "languages": {
    "fr": { "label": "Français", "values": { "Locale": "fr_FR" },
            "requires_file": "HP7/DH1_French.pck" }   // témoin de présence
  }
}
```

Trois pièges, tous mesurés et tous silencieux :

- **`requires_file` n'est pas décoratif.** Sans lui le sélecteur proposerait une langue absente du disque et le jeu se lancerait cassé. Le fichier est validé comme `executable` (pas de remontée, pas de racine, pas de lettre de lecteur).
- **Les valeurs acceptées diffèrent entre les deux parties** (`fr_FR` pour la 1, `fr` pour la 2) : les recopier de l'une à l'autre casse la seconde.
- **`values` au niveau du bloc n'est pas une commodité** : `Install Dir` doit partir dans la MÊME écriture que la langue, sinon deux invites UAC de suite.

Entry point `main.py` configures rotating-file logging, top-level exception handling, **`install_excepthook()` (rapport de crash)**, and a custom `QSplashScreen` before constructing `MainWindow`.

## UE1 engine quirks (HP1, HP2)

These are non-obvious behaviors hard-won through debugging — read before touching `pre_launch.py` or `process_monitor.py`.

- **`Running.ini` is created before each launch on purpose**: UE1 reads its absence as "previous session crashed", which triggers the wizard, which is the only reliable way to (re)initialize DirectDraw before `AttemptFullscreen`. Don't try to skip it.
- **DLLs need `Zone.Identifier` removed**, otherwise Windows blocks them and UE1 emits `Can't find file for package` then asserts in RenDev. `pre_launch.unblock_game_dlls` and `post_install.unblock_extracted` (both delegating to `win_utils.remove_zone_identifier`) handle this — preserve the calls.
- **Process restart**: the UE1 wizard re-execs a child when loading a save → `ProcessMonitor` watches the initial `Popen` + falls back on `tasklist` by exe name with a 10 s grace window. Don't shorten the grace.
- **DX11 fallback**: `IniPatch.fallback` swaps `D3D11Drv.D3D11RenderDevice` → `D3DDrv.D3DRenderDevice` when the GPU lacks feature level 11_0 (detected by `system_checks.check_d3d11_feature_level`).

## Key Conventions

- Python 3.10+ type hints (`str | Path`, `dict | None`); `pathlib.Path` everywhere.
- Threaded work uses `QThread` subclasses with `progress` / `error` + a **named completion signal** (`download_finished`, `install_finished`, `result`) — never `finished`, which would shadow the native `QThread.finished` (used for deferred cleanup of cancelled threads). Disconnect symmetrically (try/except `TypeError`) before nulling out, see `GameOperations._disconnect_*`.
- Cancelling a `QThread`: `cancel()` then `wait(3000)` before releasing the reference; on timeout (blocking network read) park it in `GameOperations._zombies` and reap via the native `finished` signal. Never let a fresh download reopen a `.part` an old thread may still hold (Windows file lock).
- All state-mutating signal callbacks live on the orchestrator; widgets are dumb consumers.
- Slots that talk to a `QDialog` after the dialog may have closed must check liveness — see `_force_update_check` for the pattern (flag + `dlg.destroyed.connect`).
- Top-level `UpdateChecker` lives on `MainWindow._update_checker`; one-shot forced checkers go into `MainWindow._extra_checkers` so they're awaited at close.
- User paths: install `~/Games/AccioLauncher`, cache `~/Games/AccioLauncher/.cache`, config `~/Games/AccioLauncher/config.json`, catalog cache `~/Games/AccioLauncher/catalog_cache.json`, logs `~/Games/AccioLauncher/accio_launcher.log` (rotating, 5 MB × 3).
- Versioning : `0.0.x` bugfix · `0.x.0` new game added · `x.0.0` all games shipped.
- `pyproject.toml` is the source of truth for deps. Runtime in `[project] dependencies`, dev tools (Pillow for icon generation, pyinstaller, pytest, pytest-qt, **ruff**) in `[project.optional-dependencies] dev`. `requirements*.txt` mirror this for `pip install -r` ergonomics.
- **`requires-python = ">=3.12"`** — et surtout PAS `>=3.10` : `enum.StrEnum` (`game_manager`) exige 3.11, donc l'ancienne borne laissait pip installer le paquet sur un interpréteur où il plante à l'import.
- **Le jeu de règles ruff est figé dans `pyproject.toml`** (`select = ["E4","E7","E9","F","W"]`). Sans cette section, « le projet est propre » dépendait du défaut de la version de ruff installée : le passage 0.15 → 0.16 a fait apparaître 119 signalements sans qu'une ligne de code change. `I`/`UP`/`B`/`SIM`/`C4`/`RET` sont des adoptions candidates documentées, à traiter en une passe dédiée APRÈS la mise en ligne. La CI lint avant de tester.
- Dark theme (`#060611` background, `#d6a72c` gold accent — l'or du pack de marque). Keep the `:focus` outline in the stylesheet — A11Y.
- **Thèmes** : tout nouveau stylesheet contenant un hex or OU une surface bleu nuit (`#060611`, `#0d0d1a`, `#0f1528`, `#16213e`, `#1a2744`, `#2c3e6b`) doit passer par `theme.themed(...)` au `setStyleSheet` ; tout nouveau `QColor` or dans un paintEvent doit utiliser `theme.accent_qcolor(alpha)`, tout voile sombre `theme.bg_qcolor(alpha)`. Écrire les couleurs en palette Poudlard (la substitution est centralisée dans `theme.py`).
- **Ko-fi sans nag** : exactement UN remerciement dans la vie du launcher (`config.kofi_milestone_thanked`, cap 10 h, toast cliquable au retour de jeu). Ne jamais en ajouter d'autre sans décision explicite de Ludo.
- Hero dynamique : au démarrage la vue ouvre sur `manager.last_played_game_id()` via `carousel.select(idx)` (qui émet `game_selected`) — ne pas appeler `set_game` directement pour un index ≠ 0, le carrousel se désynchroniserait.
- Nav clavier : ←/→ sont routés par `MainWindow._handle_global_key` (eventFilter app) même quand un bouton a le focus ; ne pas ajouter de `keyPressEvent` aux widgets pour ça. Widgets d'édition (slider, combo, lineedit) gardent leurs flèches.

## Don't reintroduce these (audit regressions)

- **`MainWindow.mouseMoveEvent` override** — redundant with the `QApplication.installEventFilter` already in place; only fires on bare MainWindow surface, not on children.
- **Direct `QDesktopServices.openUrl(QUrl(url))` calls** — use `src.ui.utils.open_url` / `open_local_path`.
- **Re-implementing download progress lines** — use `format_progress_line` / `append_part_info` from `src.core.formatting`.
- **`hasattr` / `getattr` on widget attributes** — every member must be initialized in `__init__`, full stop.
- **Slots that touch a `QDialog` after `exec()` returned without a liveness check** — see the `_force_update_check` pattern.
- **Un libellé posé à côté d'un bouton à largeur FIXE** — « Les fichiers de ce jeu ne sont pas encore en ligne » réclamait 428 px à droite d'un bouton de 300 px qui n'en laissait que 266 : phrase coupée en plein mot, à toutes les tailles de fenêtre. Mettre le texte SOUS le bouton, en `wordWrap`. Filet de sécurité : le script d'audit de troncature (mesure `fontMetrics` vs largeur réelle sur tous les jeux × états × tailles × langues).
- **Laisser la ligne méta se couper au milieu d'une information** — on lisait « ◆ 16 » en fin de ligne et « téléchargements » seul en dessous. Chaque segment passe par `_insecable()` (espaces → U+00A0) : le seul repli possible reste le séparateur ◆, donc entre deux informations entières.
- **Terminer le fond de la fiche sur autre chose que `bg_qcolor(255)`** — le carrousel est un widget FRÈRE, il ne montre pas l'illustration ; là où son dégradé est transparent on voit le fond plat du conteneur. Le dégradé bas s'arrêtait à alpha 247 et la vignette radiale creusait par-dessus : dernière ligne de la fiche à rgb(3,3,8) contre rgb(6,6,17) pour le carrousel, soit un trait CLAIR sur toute la largeur (valeur identique sur les 8 jeux — c'est ce qui a permis de l'imputer au rendu et non aux images). Le raccord `_RACCORD_PX` se peint APRÈS la vignette et sature avant le bord. Test de non-régression : écart pixel exactement 0.
- **Afficher un état NORMAL** (« espace libre : 412 Go », pastille « en ligne », « prérequis OK ») — un état ne s'affiche que lorsqu'il **DÉVIE** de la normale ; sinon c'est du bruit que l'utilisateur apprend à ignorer, et le vrai avertissement se noie avec. Décision explicite de Ludo sur l'espace disque de la barre de session.
- **Empiler plusieurs avertissements dans le bandeau** — coût mesuré : 80 px, soit le retour de la barre de défilement à 980×660, pour un second conseil qui n'est même pas actionnable.
- **Un pictogramme Unicode dans un libellé** (⚠ U+26A0, ⏸ U+23F8, ▶ U+25B6) — Cinzel ne les a pas, Windows part en repli de police et les rend en emoji couleur. Seul U+25C6 ◆ (séparateur méta) est validé.
- **Déclarer « hors ligne » sur une erreur HTTP** — un 403 (rate limit) ou un 404 prouvent que la connexion marche. Seules les erreurs de TRANSPORT comptent (`httpx.TransportError`), et une seule réponse suffit à annuler le verdict.
- **Laisser l'état hors-ligne sans re-tentative** — `MainWindow._offline_retry` (45 s, ré-armé à CHAQUE échec, arrêté dans `closeEvent`) ; sans lui, rebrancher son câble laisserait « Télécharger » grisé jusqu'au prochain démarrage.

- **Comparer des versions comme des CHAÎNES** — « 1.0 » et « 1.0.0 » sont textuellement différentes et numériquement identiques : une mise à jour fantôme s'affichait en permanence, avec un lien qui re-téléchargeait la même version. La règle vit dans `version_utils.update_disponible`, appelée par `GameManager.has_update` ET `UpdateChecker._check_catalog` ; elle refuse aussi les retours en arrière du catalogue.
- **Monkeypatcher une méthode de CLASSE Qt dans un test** — remplacer puis « restaurer » `ParticleOverlay.update` y laisse le descripteur sip de `QWidget.update` posté en attribut Python, et le process meurt sur une violation d'accès plusieurs FICHIERS de tests plus loin (le fichier fautif passe seul). Espionner par une sous-classe de test. Corollaire : un crash de suite complète qui ne se reproduit pas fichier par fichier est presque toujours un état global qui fuit — bissecter par fichier, puis par classe.
- **Jeter le résultat d'un `wait()` sur un `QThread` à la fermeture** — s'il n'a pas fini, il reste enfant et Qt le détruit vivant : abandon du processus, `0xC0000409`, aucun message et aucun rapport de crash (c'est un abandon C++, `install_excepthook` ne le voit pas). Passer par `arreter_a_la_fermeture`. Attention : `window.close()` ne détruit rien tant que `WA_DeleteOnClose` n'est pas posé, donc une sonde qui s'arrête là conclut à tort que tout va bien — il faut aller jusqu'à la sortie de la fonction, comme `main.py`.
- **Nommer un fichier de cache d'après l'URL dont il vient** — le nom d'un asset ne porte pas la version, et les deux releases de HP5 publient `hp5.7z.001` à l'identique : une part de la v1.0 restée en cache était servie pour la v1.1, et l'ancien jeu s'installait sous le numéro du nouveau, en silence. Les parts portent le nom de la DESTINATION (`hp5_v1.1.7z.001`), qui porte la version — c'est d'ailleurs pour ça que le fichier unique y échappait déjà. Corollaire réglé du même coup : le nettoyage visait `dest.with_suffix('.part')`, un fichier qui n'existe jamais en multi-parts, si bien qu'annuler HP5 laissait 2 Go dans le cache pour toujours. Un fichier resté sous l'ancien nom est ADOPTÉ si une empreinte le prouve, sinon supprimé — jamais réutilisé sans preuve.
- **Prendre `size_mb` pour la taille d'une archive** — c'est la taille du jeu une fois INSTALLÉ (mesuré : de 1,77 à 2,30 fois le téléchargement réel ; HP3 annonçait « 775 Mo » pour 337 Mo). Le poids réel vient de `GameManager.archive_size_mb`, alimenté par `extract_asset_sizes` dans la MÊME réponse que les compteurs et les empreintes — aucune requête de plus, aucune saisie à la main, et l'absence dégrade vers le catalogue. `needed_space_mb(installe, archive)` additionne les deux (+5 % de marge : le catalogue dérive de la réalité, HP5 déclare 4 600 Mo pour 4 709 mesurés) ; sans le poids réel elle garde le ×2, qui réclamait 2 001 Mo de trop.
- **Supposer que « \ » est un séparateur de chemin** — il ne l'est QUE sous Windows. Trois défauts d'un coup, tous invisibles depuis Windows : `check_path_traversal` déclarait sûr « ..\..\evil.dll » (le garde-fou anti-Zip-Slip était inopérant hors Windows), et les chemins du catalogue — écrits à la Windows, et non modifiables puisqu'ils se mettent à jour à distance — devenaient UN SEUL nom de fichier, si bien qu'aucun patch INI ne s'appliquait. Normaliser AVANT de vérifier ou de résoudre, comme le fait déjà `is_unsafe_entry`.
- **Nommer une constante `subprocess.CREATE_*` ailleurs qu'à l'import, sous garde** — elles n'existent que sous Windows, et l'`AttributeError` tombe AVANT `Popen` : la fonction devient intestable hors Windows, même en remplaçant `Popen`. Voir `self_update._DRAPEAUX_DETACHE`.
- **Laisser `write_text` choisir les fins de ligne d'un fichier qui ne nous appartient pas** — il traduit en `os.linesep` : CRLF sous Windows par coïncidence de plateforme, LF ailleurs. Les `.ini` sont écrits par UE1, un programme Windows : ils sont en CRLF partout, y compris quand le launcher tournera sous Linux (le jeu tournera sous Wine). `_INI_NEWLINE` l'impose des deux côtés — sans quoi la promesse d'aller-retour exact à l'octet ne tenait que par chance.
- **Calling `apply_pre_launch_patches` at install time** — Documents INI files don't exist yet then. Pre-launch only.
- **Faire dépendre un test du CONTENU de `games.json`** — le catalogue se met à jour
  **à distance**, sans republier le launcher : un test qui suppose ce qu'il contient
  casse à chaque livraison de jeu, loin de la ligne de code qu'il surveille. Quatre
  classes de `test_integration_smoke.py` cherchaient « le jeu sans archive » pour
  exercer le chemin « Bientôt disponible » ; la publication de HP7a/HP7b (catalogue
  0.18, 8 jeux sur 8 en ligne) les a mises au rouge d'un coup. Le comportement, lui,
  reste vivant. Remède : la fixture `make_window_jeu_a_venir` **fabrique** le cas
  (`dataclasses.replace` sur la dernière entrée, sources à `None`) au lieu de le
  chercher, plus une garde qui échoue si la fixture cesse d'en produire un — sans
  elle, les trois tests passeraient à vide en restant verts. À noter : l'ancienne
  sentinelle (« plus aucun jeu sans source — adapter ou retirer ces tests ») a
  parfaitement joué son rôle ; c'est le bon patron pour toute dépendance à une
  donnée qui bouge.
- **Double-firing `Carousel` items via `set_games` without re-emitting `game_selected`** — callers must explicitly call `_detail.set_game(...)` after a reload (see `_on_catalog_updated`).
- **Reconstruire le carrousel sans lui redire QUEL jeu est affiché** — `set_games`
  remettait l'index à 0 et surlignait l'item 0, pendant que `_on_catalog_updated`
  reposait la fiche sur le jeu courant. Au premier lancement suivi d'une mise à
  jour du catalogue (le cas NORMAL après une release), on voyait donc **HP1
  surligné sous HP6 affiché** — signalé par Ludo le 2026-08-21, capture à l'appui.
  Le second effet est pire que le premier : `select()` sort tôt quand l'index ne
  change pas, donc cliquer sur la vignette surlignée n'émettait RIEN et
  l'utilisateur ne pouvait plus revenir au jeu qu'il croyait sélectionné. La
  décision du jeu à afficher se prend **une seule fois**, avant la
  reconstruction, et se transmet à la bande (`selected_id=`). Filet :
  `tests/test_carousel.py::TestSelectionPreserveeAuReload` et deux tests
  bout-en-bout dans `TestHeroDynamique`, qui échouent tous sur le code d'avant.
- **`finished = pyqtSignal(...)` on a QThread subclass** — shadows the native `QThread.finished`; name it `*_finished` (regression tests `test_finished_not_shadowed` guard this).
- **Re-adding py7zr** — removed entirely 2026-06-10; 7z.exe bundlé is the only 7z extractor (cancel, progress, BCJ2, multi-volume). Don't reintroduce the dependency or the `.001` concatenation step in the downloader.
- **Changing `install_path` without `manager.refresh_states()`** — stale INSTALLED states make « JOUER » fail silently (see `MainWindow._on_config_changed`).
- **Uninstalling before the replacement download finishes** (`switch_version`) — download first, uninstall in `_on_download_finished`; revert paths use `redetect_state`.
- **A dedicated `QTimer` per decorative animation** — subscribe to `src.ui.ticker.Ticker` instead (one clock for particles/stars/glow, pausable globally).
- **`label.mousePressEvent = lambda …`** — invisible to keyboard users; use `src.ui.clickable_label.ClickableLabel`.
- **Remettre des traductions dans du Python** (un dict `_EN` en dur, une liste de langues codée dans `settings_panel`) — les fichiers `src/data/i18n/*.json` sont la seule source, et la découverte doit rester automatique : sinon un traducteur bénévole doit éditer du code.
- **Traduire le catalogue via `tr()`** — le catalogue se met à jour à distance sans release ; ses traductions DOIVENT voyager dans `games.json` (bloc `i18n`), sinon tout jeu ajouté reste français jusqu'à la prochaine build.
- **Recopier une empreinte SHA-256 à la main dans `games.json`** — GitHub publie la sienne pour chaque asset et le launcher la récupère seul (`extract_asset_digests`). Une empreinte saisie à la main peut être fausse ou oubliée, et une empreinte fausse est PIRE que pas d'empreinte : elle inspire une confiance qu'elle ne mérite pas. Les champs `sha256` / `sha256_parts` du catalogue restent réservés aux archives hébergées **ailleurs** que sur GitHub.
- **Croire que la vérification protège d'un dépôt compromis** — GitHub atteste ce qu'il stocke : elle détecte une corruption de transport (troncature, proxy, disque), pas une archive remplacée à la source. Le catalogue étant sur le même compte, une empreinte écrite à la main n'y changerait rien.
- **Écrire un JSON de langue ou de catalogue avec `ensure_ascii=True`** — les accents (et demain le CJK) partent en `\uXXXX` et le fichier devient illisible en revue de PR, ce qui tue la contribution.
