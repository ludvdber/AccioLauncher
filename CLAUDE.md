Guide de travail pour Claude Code sur ce dépôt. **Toute règle ici a été payée une fois** : elle porte sa mesure, pas son récit.

## Project Overview

Launcher PyQt6 pour 8 jeux Harry Potter PC (Windows 10/11). **Interface et commentaires en français.** Python 3.12+ (`build.bat` préfère 3.14, replie sur 3.13 puis 3.12).

**Ne pas passer à Python 3.15** : PyInstaller met des mois à suivre une version majeure, et le gain serait nul ici.

**Linux est un objectif déclaré** : tout appel win32 derrière `sys.platform == "win32"` avec un repli sensé (patron : `self_update.can_self_update`, `win_utils`, `system_checks`, `game_registry.disponible`). Jamais de lettre de lecteur hors code gardé.

**Le registre sous Linux** : il n'y en a pas, mais le jeu tournera sous **Wine, qui a le sien**. Le travail n'est pas à supprimer, il est à rebrancher sur `wine regedit`. Tout passe par `game_registry.disponible()` — un seul point à changer, plus `_ecrire_eleve`.

**Portage Linux : `docs/LINUX.md` fait foi** (audit `fichier:ligne`, contenu RELEVÉ des archives, décisions : umu puis wine, préfixe partagé, chemins du préfixe, surcharges de DLL, AppImage).

## Commands

```bash
pip install -r requirements.txt && python main.py     # lancer depuis les sources
python -m pytest                                      # toute la suite
python -m pytest tests/test_config.py::TestConfig::test_defaults
python -m ruff check .                                # jeu de règles FIGÉ dans pyproject.toml
pip install -r requirements-dev.txt && build.bat      # → dist/AccioLauncher.exe
```

`build.bat` enchaîne icône → lint → tests → géométrie (vraies polices) → PyInstaller, et **s'ARRÊTE au premier échec** : un exe publié avec une régression coûte plus cher que 20 s d'attente.

## Architecture

Deux couches sous `src/`, reliées par un orchestrateur (`game_operations`) et un bus de signaux Qt.

### `src/core/` — logique métier (pas de widgets, sauf QThread/QObject/pyqtSignal)

- **`config.py`** — dataclass `Config`, sauvegarde JSON atomique (tmp+rename). `get_documents_dir()` passe par `SHGetFolderPathW` (OneDrive / Documents redirigés). Chemins différents en mode gelé (`sys._MEIPASS`). `APP_VERSION` vit ici, synchronisé avec `pyproject.toml`.
- **`game_data.py`** — dataclasses gelées du catalogue. `load_catalog()` fusionne `src/data/games.json` (embarqué) et `~/Games/AccioLauncher/_Launcher/catalog_cache.json` — **le plus grand `catalog_version` gagne (strictement)**. `GameData.from_dict` **valide les chemins `executable` au parsing** (refuse `..`, absolu, lettre de lecteur). **Le catalogue porte ses traductions** (bloc `i18n` par jeu et par version), résolues au parsing par `_loc()` : `set_language()` tourne avant `load_catalog()`, donc `game.name` est déjà traduit et aucun site d'affichage ne change. Raison : **le catalogue se met à jour à distance**, un jeu ajouté doit arriver traduit sans republier l'exe. `_loc` refuse une valeur qui changerait le TYPE d'un champ. Porte aussi `warning` (traduisible) et `warning_url` (**https uniquement, validé au parsing** — seule chaîne du catalogue qui atteigne le navigateur). Affichés par `ActionPanel._build_alerts` au dernier rang, en NOT_INSTALLED et INSTALLED. Remplissage i18n : `tools/apply_catalog_i18n.py` (idempotent).
- **`game_manager.py`** — possède `Config`, le catalogue, la carte des `GameState` et les empreintes SHA-256 (`set_asset_digests` / `expected_hashes`). `expected_hashes(version)` : catalogue (`sha256`/`sha256_parts`) d'abord, puis les empreintes publiées par GitHub ; `(None, [])` si rien → vérification sautée, jamais un échec. Recherche **insensible à la casse** du nom d'asset (cas réel : « hp6.7z.001 » vs « HP6.7z.001 ») ; une ambiguïté de casse est ignorée plutôt que devinée. Multi-parts : **tout ou rien**. `refresh_states()` re-détecte depuis le disque (après changement d'`install_path` ; préserve DOWNLOADING/INSTALLING). **`_backfill_missing_versions`** : un jeu INSTALLED sans entrée `installed_versions` reçoit la version recommandée, sinon `has_update` serait muet à vie. MàJ de jeux notifiées par `MainWindow._notify_game_updates` (recompte LOCAL + toast cliquable — le signal `update_counts` ne voit que le distant). Temps de jeu : `add_playtime` / `get_playtime` / `last_played` ; sessions < 10 s ignorées ; UNE ligne discrète dans `InfoPanel`, cachée si jamais joué.
- **`game_registry.py`** — lecture/écriture des valeurs de registre d'un jeu. Trois contraintes relevées sur une vraie installation : **vue 32 bits** (`KEY_WOW64_32KEY`), **valeurs nommées ET typées** (`Language` en REG_SZ, `1.0\\Language` en REG_DWORD), **HKLM exige l'élévation** — d'où : on lit (gratuit), on compare, on n'écrit que si ça diffère. L'écriture élevée passe par un `.reg` UTF-16 + `regedit /s` dans un **dossier temporaire à nom aléatoire** (`mkdtemp` — un chemin fixe laissait remplacer le fichier avant son import ADMINISTRATEUR), **et on relit derrière** (`regedit /s` est muet même en échec). `refus_de_cle` / `refus_de_valeur` sont PURES et forment la seule barrière entre le catalogue distant et le registre. **`comparer(...)` rend `{nom: (actuel, voulu)}`** : `ecrire_valeurs` passe ces écarts au rappel, qui affiche « remplace : … ». Sur une machine où EA a installé le jeu, `Locale` et `Install Dir` sont DÉJÀ posés ailleurs — le cas normal est un remplacement. **`ecrire_valeurs(..., confirmer=…)`** prévient JUSTE AVANT d'écrire et seulement s'il y a une écriture : sous HKLM ça enchaîne sur UAC, et une autorisation qui surgit sans raison connue se refuse. Comme le rappel ne part qu'en cas d'écart réel, prévenir TOUJOURS ne devient jamais un nag. **`launch_game(..., avertir=…)`** signale une écriture nécessaire qui n'a pas abouti : le lancement continue, mais l'appelant DOIT distinguer l'échec du refus délibéré (`on_play` retient `accepte`). **`disponible()`** dit si ce système a un registre atteignable.

  **Ce que lisent réellement HP7 parties 1 et 2** (relevé dans `hp7.exe` / `hp8.exe`, pas deviné) : les deux lisent **`Locale`** et **`Install Dir`**, **jamais `Language`**, contrairement à ce qu'écrit l'installeur EA. Les valeurs acceptées **DIFFÈRENT** : partie 1 `en_UK fr_FR it de es pl ru`, partie 2 `en fr it de es pl ru`. C'est ce qui explique la contradiction entre les guides (« `fr` ») et le registre d'une vraie machine (« `fr_FR` ») : les deux avaient raison, pour des parties différentes.
- **`game_language.py`** — langue d'un jeu, extrait de `game_manager` (763 → 639 lignes). Les fonctions prennent `game` et `config` EXPLICITEMENT au lieu de lire `self`, donc s'exercent sans construire de manager. `langues_disponibles(game)` filtre sur la PRÉSENCE du fichier témoin (`requires_file`) : le registre ne fait que SÉLECTIONNER, les fichiers viennent du disque d'origine — HP7 partie 1 n'embarque que `DH1_French.pck`, la partie 2 les sept. **`valeurs_registre(game, code)`** compose les valeurs COMMUNES du bloc (`values`, `%INSTALL_DIR%` substitué) **plus** celles de la langue, langue en dernier : une seule écriture, donc **une seule invite UAC** au lieu de deux à la suite. `apply_game_language` applique AVANT de persister, sinon un UAC refusé laisserait en config un choix que le registre n'a pas pris. Les tests bouchonnent `src.core.game_language.registre.*`.
- **`pre_launch.py`** — fonctions pures de pré-lancement UE1 (substitution, patches INI, création/suppression de fichiers, déblocage DLL). **`restaurer_configs_manquantes`** recopie une config livrée qui a DISPARU de Documents, avant les patchs (règle plus bas). **`env_de_lancement(dpi_aware)`** ajoute `__COMPAT_LAYER=HighDpiAware` sous Windows **pour un jeu qui le déclare au catalogue**, `None` sinon (ce que `Popen(env=None)` attend). **Deux jeux sur huit le déclarent** (HP7a/HP7b) — consigne explicite : eux seuls posaient le problème, les six autres n'ont pas été mesurés. La variable ne persiste RIEN (portée au processus), là où l'onglet Compatibilité est indexé par CHEMIN COMPLET.
- **`downloader.py`** — `QThread` sur httpx en streaming (**httpx importé paresseusement dans les méthodes**, test AST de régression). HTTPS only, multi-part avec reprise. **Plafond d'octets** = `expected_size_mb × 1.5` (`SIZE_OVERHEAD_FACTOR`) ; `0` le désactive. **SHA-256 incrémental pendant le stream** (plus d'UI figée à 100 %) ; `_verify_sha256` ne sert plus qu'aux parts déjà en cache ; mismatch → suppression + réessai. **Boucle d'écriture UNIQUE** (`_ecrire_chunks`, `_refuser_taille_annoncee`) : elle existait en deux exemplaires (nominal et reprise HTTP 416), le second sans aucun test. `TestReprise416` prouve la reprise par la SÉQUENCE des requêtes (une avec `Range`, puis une sans).
- **`self_update.py`** — auto-update en un clic (Windows gelé) : `.bat` attend la mort du processus, remplace l'exe, relance. `can_self_update()` garde le chemin. **`relaunch_after_exit()`** réutilisé par « Redémarrer maintenant » et le dialogue de plantage. **Le `.bat` s'écrit avec `newline=""`** (sinon `\r\r\n` → cmd coincé dans `:wait`), se lance avec `CREATE_NO_WINDOW` + DEVNULL, **jamais `DETACHED_PROCESS`** (qui bloque `tasklist | find`), et **avec `env=_clean_pyinstaller_env()`** : sans purge des `_PYI_*` (+ `PYINSTALLER_RESET_ENVIRONMENT=1`), l'exe onefile relancé se croit enfant de l'instance morte et crashe « Failed to load Python DLL ». Voir pyqt-pitfalls #18 et #20.
- **`installer.py`** — orchestrateur `QThread` mince (extraction → déblocage → config_files → nettoyage). Délègue à `extractors.py` et `post_install.py`.
- **`extractors.py`** — extraction pure avec protection Zip Slip : `extract_7z` (**7z.exe bundlé, unique extracteur 7z** — progression fine, annulation immédiate, multi-volume `.7z.001` natif ; py7zr retiré), `extract_zip`. Les multi-parts émettent le `.001` brut (pas de concaténation) ; `Installer._delete_archive` retire tous les volumes.
- **`post_install.py`** — `unblock_extracted`, `apply_config_files` (avec sauvegarde `.bak`), **`ranger_dans_sous_dossier`** (voir « Le sous-dossier `pc` de HP7 »). `apply_registry` **a été supprimé** avec toute la plomberie `registry` : un bloc `registry` dans `games.json` est désormais simplement IGNORÉ, ce qui est franc — avant, il était accepté au parsing puis échouait **en silence**.
- **`trailers.py`** — bandes-annonces, **hors de l'exécutable**. Deux vidéos faisaient passer l'exe de **74 à 160 Mo** ; les huit l'auraient mené au-delà de 500, pour un ornement facultatif. Publiées en assets de release (`trailers-v1`), déclarées par le bloc `trailers`, téléchargées à la demande. Module PUR : `chemin_local`, `present`, `manquantes`, `fichiers_perimes`, `supprimer_tout`, `chemin_a_jouer`. **Le fichier LOCAL porte la version** (`hp1_video_v1.0.mp4`) alors que l'asset non : sans ça, améliorer une bande-annonce ne remplacerait jamais l'ancienne. Corollaire obligatoire : `fichiers_perimes` fait le ménage AVANT chaque téléchargement (sinon le poids double à chaque révision), et **seulement** sur le motif `<id>_video_v<version>.mp4` — le dossier appartient à l'utilisateur.
- **`thread_utils.py`** — **`arreter_a_la_fermeture(thread, nom)`**, geste d'extinction partagé par `GameOperations.cancel_all` et `UpdateDispatcher.shutdown`. En session un thread récalcitrant se GARE (`_zombies`) ; à la fermeture, non — Qt le détruit avec son parent, ce qui **abandonne le processus** (`0xC0000409`, sans message ni rapport). Attendre plus est exclu (`read` httpx à 120 s), d'où `terminate()` + `wait()`. Filet : `tests/test_fermeture_threads.py`, en SOUS-PROCESSUS, qui rejoue l'ancien code en exigeant qu'il plante.
- **`stats.py`** — journal des sessions, et tout ce qui s'en déduit. On enregistre l'ÉVÉNEMENT (jeu, quand, durée) dans `_Launcher/sessions.json` ; **tout le reste est un calcul** — une statistique pas encore imaginée sera calculable **rétroactivement**. **Invariant à ne jamais assouplir** : le temps joué AVANT le journal (`herite`) compte dans les totaux mais dans RIEN d'autre, faute de date. La séparation est STRUCTURELLE, pas un drapeau : `Historique.sessions` ne contient que de vraies sessions, `temps_par_jeu` est la seule fonction qui additionne les deux (`TestHeriteNEntreQueDansLesTotaux`). **Chemin résolu À L'APPEL** depuis `config.CONFIG_FILE_PATH` — c'est ce que `conftest.py` redirige ; un chemin figé aurait échappé à cette garde, qui existe parce que de vraies statistiques ont été écrasées par un test. Journal illisible → **mis de côté** (`.corrompu`), jamais écrasé. `amorcer` idempotente ; un échec d'écriture ne remonte jamais.
  Trois ajouts nés du même constat — le launcher OBSERVAIT des choses et les jetait : ① **`Tentative`** (lancement < 10 s avec son code de sortie) — un jeu qui refuse de démarrer ne laissait AUCUNE trace, alors que c'est la signature du défaut du sous-dossier `pc`. **Liste SÉPARÉE**, jamais un drapeau. ② **Partie en cours** (`ouvrir_session`/`battre_session`/`fermer_session`/`recuperer_session_interrompue`) — une session n'était écrite qu'à la FERMETURE, donc **plus une partie était longue, plus elle avait de chances d'être perdue** : biais silencieux contaminant moyenne, record, séries et plages horaires. Le battement (1/min) fait que la durée rattrapée est OBSERVÉE ; sans battement on n'écrit rien (mieux vaut un trou qu'un chiffre faux). ③ La grâce de 10 s n'est plus comptée comme du temps de jeu.
- **`choixpeau.py`** — le Choixpeau du premier lancement. Quatre questions, une maison, **aucun hasard** : `repartir()` est PURE, sinon ce serait un bouton « thème aléatoire » déguisé. La maison **PROPOSE** le thème (pré-sélectionne le combo suivant, modifiable). Sans réponse, rend `""` et Poudlard est conservé. Les identifiants de maison SONT ceux des thèmes — aucune table à tenir. La dernière question pèse double, une égalité revient au **premier choix**. L'ordre des réponses change d'une question à l'autre (sinon on résout le questionnaire sans le lire). `tr()` appelé À L'APPEL, pas à l'import.
- **`sauvegardes.py`** — quelle partie a nourri quelle sauvegarde. On relève nom + dates (**jamais le contenu**) au lancement et à la fermeture ; celle qui a changé reçoit la partie. Stocké dans `_Launcher/sauvegardes.json`, **SÉPARÉ du journal** : le temps de jeu ne dépend jamais de cette attribution, donc ne peut pas baisser. Emplacements déclarés par le **bloc `saves`** parce que le nom du dossier dépend de la LANGUE d'installation. **Portabilité** : aucun chemin Windows (racine abstraite, motifs en « / », antislashs normalisés, lettres refusées). **Un test ne doit jamais supposer une date de CRÉATION** : Linux n'expose pas `st_birthtime`. `racines()` est remplacée par `conftest._sauvegardes_hors_du_vrai_disque`.
- **`season.py`** (déplacé de `src/ui/` — il n'importe pas Qt) — l'Almanach porte le **calendrier** et le **`Profil`** de chaque ambiance, tous deux purs ; `particles.py` ne sait plus que PEINDRE. Avant, ces nombres vivaient dans une cascade de `if` au milieu d'un constructeur : deux ambiances y tenaient, cinq en auraient fait un mur. **Ajouter un jour est une ligne de table.** Dates : `rentree` (1-7 sept.), `anniversaire` (juillet), `bataille` (mai), `halloween` (octobre), `noel` (déc.-6 janv.). **Une date de JOUR l'emporte sur une période de mois.** Contrairement au thème, appliqué **EN DIRECT** (`SettingsDialog.season_changed` → `ParticleOverlay.apply_season`). Le sélecteur lit `SEASONS`/`SEASON_LABELS` et ne tient plus sa propre liste. Formes : `point`, `flocon`, `enveloppe`, `flamme` ; une forme inconnue retombe sur le point. **Coût mesuré à 1270×844** (30 ips) : aucune 29 ms/s · halloween 58 · noel 60 · rentree 32 · anniversaire 69 · bataille 28, zone sale 1-4 %. **La taille d'une forme est un seuil de lisibilité, pas un réglage** : les enveloppes à 3-5,5 px se lisaient comme de la poussière ; il leur faut une douzaine de pixels, en contrepartie de quoi on en met moins.
- **`almanach.py`** — le fait du jour. Table de 20 dates exactes, fonds de 24 faits tagués : **une date exacte l'emporte, sinon un fait DE SAISON, sinon le fonds commun**, tiré par le quantième donc DÉTERMINISTE (un fait qui saute à chaque ouverture est du bruit). **Toutes les dates sont canoniques et VÉRIFIÉES** ; une date discutée entre sources n'entre pas dans la table. **Affiché à la place de « Prêt »** — double gain : « Prêt » est un état NORMAL, et le fait occupe une place existante. Tout message réel passe DEVANT. Réglage `config.faits_du_jour`. Les textes passent par `tr()` À L'APPEL, donc invisibles à l'extracteur AST — c'est `TestChaqueFaitEstTraduit` qui réclame leur traduction.
- **`scolarite.py`** — les sept années. **Aucune donnée nouvelle** : l'année vient du catalogue (`GameData.annee`), le reste de l'état d'installation et du temps de jeu. ① **L'année vient du catalogue, JAMAIS du rang** (la Coupe du Monde de Quidditch n'est l'année de personne). ② **Une année peut porter plusieurs jeux** (les deux Reliques = 7ᵉ). ③ **On ne prétend pas savoir qu'un jeu est TERMINÉ** : l'année en cours est la plus haute année COMMENCÉE, ce qui est observable. `annee_courante` rend 0 = « la lettre vient d'arriver », pas « échec ».
- **`i18n.py`** — **FR / EN / ES**, sans Qt. Les chaînes françaises SONT les clés ; les traductions vivent dans **`src/data/i18n/<code>.json`** (`_meta` + `strings`), plus jamais dans le Python (guide : `docs/TRANSLATORS.md`). **Ajouter une langue = déposer un fichier** (`available_languages()` le découvre). Repli en cascade **langue → anglais → clé française, par CHAÎNE**, donc une traduction partielle est acceptable. Un fichier dans `~/Games/AccioLauncher/_Launcher/i18n/` est **fusionné par-dessus** l'embarqué. **Le défaut est l'ANGLAIS** et le premier lancement demande la langue à l'écran 1. **Toute chaîne visible doit passer par `tr()` ET exister dans chaque `<code>.json`** — `TestCouverture` extrait les `tr()` par AST, **et `TestPasDeClesOrphelines` tient le sens INVERSE** : une clé dont le texte a disparu doit disparaître aussi (34 s'étaient accumulées — le coût n'est pas le poids du fichier, c'est qu'un bénévole les traduit). La clé doit exister comme LITTÉRAL dans `src/` ou `main.py`, pas forcément dans un `tr()`. **`main.py` fait partie du balayage** : il porte les cinq étapes du splash.
- **`updater.py`** — `UpdateChecker` (QThread) : catalogue + launcher + **compteurs ET empreintes**. `extract_asset_digests` (pure) lit le champ `digest` — **aucune requête de plus**, la réponse est déjà là pour les compteurs. `aggregate_download_counts` (pure) fait MAX des parts puis SOMME des versions ; affiché « ◆ 1 234 téléchargements » (losange U+25C6, jamais de flèche ni d'emoji). **AUCUN seuil de présentation** : le vrai chiffre dès 1. Le `> 0` n'en est pas un : `download_count` rend 0 quand la réponse GitHub n'est pas arrivée, donc zéro veut dire « je ne sais pas ». **Diagnostic réseau** : `network_status(bool)` — `is_online` ne vaut False que si AUCUN serveur n'a répondu ET qu'au moins une tentative a échoué au TRANSPORT ; une réponse HTTP, fût-elle un 403, prouve la connexion. **`extract_release_notes`** (pure) rabote le Markdown, supprime les blocs de code (l'empreinte et `gh attestation verify` occupent la moitié de nos notes) et coupe à 12 lignes.
- **`echecs.py`** (pur) — classe l'échec d'un téléchargement (`cause_de` : connexion, disque plein, antivirus, accès refusé, empreinte, fichier inattendu, 404, limite, serveur) et rédige la boîte (`explication` + octets conservés). `Downloader.error` porte `(message, Echec)`.
- **`diagnostic.py`** (pur) — identité (version, exe/sources, Windows, Python, Qt) et écrans en pixels PHYSIQUES avec leur échelle, première et deuxième ligne de chaque session : hors ligne la version n'apparaissait jamais, et trois défauts de ce projet n'existaient qu'à 125 %. Fabrique aussi le bloc « Copier les informations de diagnostic » et l'en-tête du rapport de plantage ; porte `scrub_user_paths`.
- **`single_instance.py`**, **`discord_presence.py`** (IPC local, sans dépendance ; `DISCORD_CLIENT_ID` requis sinon no-op ; les boutons d'activité ne sont visibles que des AUTRES), **`win_taskbar.py`** (ITaskbarList3 en ctypes, no-op hors Windows).
- Aides : `formatting.py` (`format_progress_line`, `format_playtime`, `format_relative_date`, **`format_duree_compacte`** — « 2 h 40 min », minutes sur DEUX chiffres ; distinct de `format_playtime` qui suffixe « de jeu » : juste dans une fiche, fautif dans une grille dont l'en-tête l'a déjà dit), `win_utils.py` (`remove_zone_identifier`, `commande_systeme`), `version_utils.py` (`compare_versions` numérique).

  **`system_checks.py`** — tests VC++ / DX11 `@functools.cache`d, `VCREDIST_URL` **à côté** du test qui détecte le manque. **Prérequis PAR JEU déclarés par le catalogue** : `PREREQUIS` mappe un identifiant (`vcredist_x86`, `vcredist2005_x86`, `vcredist2008_x86`) vers (test, page d'aide), et `prerequis_manquants(('vcredist_x86', *game.requires))` est la SOURCE UNIQUE de `launch_game` ET du bandeau. **HP7 partie 1 exige VC++ 2005, partie 2 VC++ 2008** — détectés via l'assembly WinSxS et NON le registre (les clés `SideBySide\Winners` n'existent pas sur Windows 11, vérifié). Un identifiant inconnu est ignoré, jamais bloquant : un catalogue en avance ne doit pas verrouiller un launcher plus ancien. `launch_game` lève `RuntimeError('prerequis_manquant:<id>')` ; `invalidate_vcredist_cache()` au retour dans la fenêtre après un clic « Installer ». `needed_space_mb(installe, archive)` additionne les deux (+5 % : le catalogue dérive du réel — HP5 déclare 4 600 Mo pour 4 709 mesurés) ; **source unique** partagée par le bandeau et la vérification au clic.

### `src/ui/` — widgets PyQt6

- **`main_window.py`** — hôte sans cadre. Le suivi souris passe par un **unique** `QApplication.installEventFilter(self)`. **Taille d'ouverture adaptative** (62 % × 76 % de `availableGeometry()`, bornée 980×660 → 1320×880, centrée) : l'ancien 1200×800 fixe ne tenait pas sur un 1366×768. **La vérification des mises à jour est inconditionnelle** (le réglage `check_updates` a été supprimé) : sans réseau chaque étape échoue proprement, et ne pas vérifier privait surtout des empreintes SHA-256. Les tests neutralisent `_start_update_check`, jamais un réglage. Edge-resize sans cadre (`startSystemResize`, marge 6 px). **`closeEvent` est le point de passage UNIQUE de toutes les sorties** : sous Qt 6.11, `QApplication.quit()` envoie un `QCloseEvent` et un `ignore()` ANNULE la sortie ; croix, Alt+F4 et « Quitter » du tray y convergent, et `_quit_app` lit la valeur de retour de `close()`. `_confirmer_fermeture()` demande confirmation **quand une opération est en cours**, avec un message qui DIFFÈRE selon `ops.phase` (un téléchargement reprend, une installation est à refaire) : « êtes-vous sûr ? » sans dire ce qu'on risque fait deviner, et qui devine clique. Deux chemins l'exemptent (`_fermer_sans_demander()`) parce qu'un `.bat` y attend DÉJÀ la mort du processus. **Plafond de lignes testé** — un plafond qu'on ne rabaisse jamais devient un compteur.
- **`window_chrome.py`** — bords saisissables. ### Journal, sortie et CI

**`main.py`** configure le logging rotatif, l'exception de haut niveau, `install_excepthook()` et le splash avant `MainWindow`. Fichier en **INFO dans l'exe**, DEBUG depuis les sources, `ACCIO_JOURNAL=debug` pour rendre le détail à l'exe.

**`main()` sort par `os._exit(code)` après `logging.shutdown()`**, jamais par `sys.exit(app.exec())` : pendant la finalisation de l'interpréteur, sip détruisait les objets C++ dans le désordre — violation d'accès dans `sip.cp314-win_amd64.pyd` à **2 fermetures sur 8**, et 5 fois au journal Windows ; **0 sur 14** après. `PyQt6.sip` n'a plus `setdestroyonexit`. Tout ce qui doit être écrit l'est dans `closeEvent`.

**Paquets CI figés avec empreintes** (`.github/requirements/*.txt`, `--require-hashes`) : un `tests.txt` résolu en `--universal` couvre Windows 3.12/3.14 et Linux ; `build.bat` n'en dépend pas. **CodeQL** tourne en workflow (Scorecard ne reconnaît pas le « default setup », ni Bandit, comme SAST ; les deux ne peuvent coexister). **Fuzzing** (`fuzz.yml`, Atheris, Linux) : `fuzz/invariants.py` écrit en assertions ce que promettent les barrières entre le catalogue DISTANT et la machine ; `tests/test_fuzz.py` les rejoue sous Windows. Il a trouvé `"year": 1e999`, les séparateurs de ligne Unicode dans un `.reg`, et des noms d'archive que les deux gardes Zip Slip jugeaient différemment.

**`tests.yml`** — pytest sur `windows-latest` en **3.12 ET 3.14** (3.12 est le plancher déclaré et n'avait jamais été testé : `Path.read_text(newline=…)`, apparu en 3.13, y cassait `tools/sync_trailers.py`) + smoke `ubuntu-latest` offscreen, **bloquant**. Ce job fut rouge à CHAQUE run depuis sa création : ne bloquant rien, personne ne le regardait. Remis au vert, **puis rouge de nouveau quatre semaines** pour la même raison — 25 tests de LANGUE DE JEU supposaient un registre Windows sans le dire. Remède : la fixture **`registre_atteignable`**, à demander pour tout nouveau test de langue de jeu. **Tant qu'un job n'est pas bloquant, un rouge y dure des semaines. Ne pas remettre `continue-on-error`.** Pour reproduire : `python:3.14-slim` + les bibliothèques Qt du workflow **+ `libgssapi-krb5-2`** (QtNetwork la réclame) **+ `fontconfig fonts-dejavu-core fonts-liberation`** — sans le paquet `fontconfig`, la bibliothèque est là mais ne trouve aucune police, ce qui fait un troisième environnement.

**Releases construites par la CI** (`release.yml`). **Tout se fait depuis le site GitHub** : Actions → release → Run workflow, case « Créer la release » cochée. Le tag se DÉDUIT d'`APP_VERSION` (refus hors de `main` ou si la version a déjà un tag) et naît sur le commit construit (`--target`) — **pas de déclenchement sur tag**, publier le brouillon en créant un relancerait un build voué à l'échec. Attestation de provenance Sigstore sur l'exe, release en **BROUILLON**, notes pré-remplies depuis `.github/release-notes.md`. Rien n'est public avant « Publish release », et l'auto-update ne voit pas un brouillon. Case décochée = build d'essai. `build.bat` le permet par `CI` et `ACCIO_PY`. **Toutes les actions épinglées par empreinte de commit**, Dependabot tient les deux à jour. `LICENSE` ne contient QUE le texte GPL v3 officiel (sinon GitHub affiche « Other ») : les termes additionnels de l'article 7 vivent dans `ADDITIONAL-TERMS.md`. **Licence : GPL-3.0-only depuis le 2026-09-24** (MIT jusqu'à la 1.0.6) — la plus stricte que permet PyQt6 ; interdire la redistribution exigerait PySide6 ou une licence Riverbank.

## Catalogue

`src/data/games.json` (embarqué) est bumpé avec le distant (`accio-launcher-games`). **Les garder en phase** — un `executable` faux donne des échecs silencieux de lancement et de désinstallation. Le contenu doit être identique ; l'indentation et les fins de ligne peuvent différer.

**Bloc `trailers`** (racine) :

```jsonc
"trailers": { "hp1": { "version": "1.0", "url": "https://…/hp1_video.mp4", "size_mb": 82 } }
```

Quatre règles payées ailleurs : **n'y déclarer que ce qui EXISTE** (huit vidéos dont six en 404 = six échecs par tentative) ; **`version` et l'identifiant finissent dans un NOM DE FICHIER** et viennent du catalogue DISTANT, donc `_JETON_SUR` refuse tout ce qui n'est pas `[A-Za-z0-9][A-Za-z0-9._-]*` (sans ça, `"version": "../../evil"` écrirait hors du dossier) ; **`url` en https uniquement** ; **pas de `sha256` à la main** (GitHub publie la sienne, `trailer_hash` la récupère). Noms d'assets : `<id>_video.mp4`, identifiant du CATALOGUE (`hp7b` est livré par la release `hp8-v1.0`).

**Le bloc ne s'écrit pas à la main** : `python tools/sync_trailers.py src/data/games.json ../accio-launcher-games/games.json` lit la release (`--tag`, défaut `trailers-v1`) et pose URL et `size_mb` d'après ce qui est RÉELLEMENT publié. Un `size_mb` sous-estimé fait avorter un téléchargement sain (plafond ×1,5, d'où l'arrondi au SUPÉRIEUR). Idempotent, préserve CRLF et indentation, signale les identifiants sans jeu. Sans `--version`, les jeux déjà déclarés gardent la leur.

**Champ `dpi_aware`** (HP7a/HP7b uniquement) — `"dpi_aware": true`. Windows virtualise un programme qui ne se déclare pas conscient du DPI et multiplie par le facteur tout ce qu'il demande, **fenêtre comprise** : **3200×1800 sur un écran de 2560×1440 à 125 %**. Trois choses : **ce n'est PAS un réglage de résolution** (l'énumération Direct3D passe par le pilote, hors virtualisation — le jeu retient un légitime 2560×1440, c'est la fenêtre qui est agrandie ensuite, d'où « je comprends pas ») ; **le champ est par JEU et le reste** (`is True` au parsing : une chaîne non vide suffirait sinon à changer le lancement d'un exécutable sur la foi d'un fichier venu du réseau) ; **le défaut est nul à 100 %**, donc invisible à toute la suite.

**Champ `annee`** (hp1-hp7b) — `"annee": 3`, 1 à 7, absent ou 0 = hors programme. **`hp7a` comme `hp7b` valent 7.** **L'année ne se déduit JAMAIS du rang.** Validé par `_annee_valide` ; **les booléens sont refusés explicitement** — `True` EST un `int`, et `"annee": true` vaudrait « 1ʳᵉ année ».

**Bloc `contributors`** (racine) — `{ "name", "role", "url"?, "i18n" }`. Dans le CATALOGUE et non le code, parce que **remercier quelqu'un ne doit pas attendre une release** : une traduction rendue un mardi doit pouvoir être créditée le mardi, sinon la personne voit passer trois versions sans son nom et n'en propose pas une deuxième. `url` passe par la MÊME validation https que `warning_url`. Les traducteurs restent dans `_meta.translators` de leur fichier de langue — ils s'y ajoutent dans la même contribution.

**Bloc `language_registry`** (HP7a/HP7b) :

```jsonc
"language_registry": {
  "root": "HKLM", "view": 32,
  "key": "SOFTWARE\\Electronic Arts\\Harry Potter and the Deathly Hallows Part 1",
  "values": { "Install Dir": "%INSTALL_DIR%\\" },
  "languages": { "fr": { "label": "Français", "values": { "Locale": "fr_FR" },
                         "requires_file": "HP7/DH1_French.pck" } }
}
```

Trois pièges mesurés et silencieux : **`requires_file` n'est pas décoratif** (sans lui on propose une langue absente du disque et le jeu se lance cassé ; validé comme `executable`) ; **les valeurs diffèrent entre les deux parties** (`fr_FR` vs `fr`) — les recopier casse la seconde ; **`values` au niveau du bloc n'est pas une commodité** — `Install Dir` doit partir dans la MÊME écriture que la langue, sinon deux invites UAC de suite.

**Bloc `saves`** — `root` ∈ documents/localappdata, `folders` (glob), `files`, `exclude`, `first`. Le nom du dossier dépend de la LANGUE d'installation (« Harry Potter et le prisonnier d'Azkaban »…). Motifs validés comme `executable`, sans « : » ni « ** ». HP4 n'a pas de bloc.

| `HP7\hp7.exe` (ce que posent les archives) | sortie **0** en 0,5 s |
| `D:\HP7\hp7.exe`, copie d'origine intacte | sortie 0 en 0,5 s |

Trois pièges payés : **ce n'est PAS un plantage** (code 0, aucun fichier écrit, rien au journal d'événements, pas de fenêtre — le jeu part par le chemin « insérez le disque » et se tait ; c'est l'exécution qu'il faut observer, pas les journaux) ; **le NOM compte**, pas la profondeur ; **l'emplacement absolu n'y est pour rien** — la copie d'origine échoue à l'identique, donc la théorie « il faut le dossier d'installation d'origine » décrit le bon symptôme et la mauvaise cause.

Le launcher **range après extraction** plutôt que de republier 12 Go : `post_install.sous_dossier` (validé par `_sous_dossier_valide` — un seul composant, `_JETON_SUR`, jamais un chemin : cette valeur vient du catalogue DISTANT et sert à DÉPLACER tout un jeu), appliqué par `ranger_dans_sous_dossier`. Renommage sur le même volume : **133 fichiers, 4,4 Go, 0,07 s**. **Idempotente** et **écrase** — sur une réparation, l'archive repose des fichiers à plat par-dessus une installation rangée. Corollaire : `executable` et `requires_file` désignent l'emplacement FINAL.

## UE1 engine quirks (HP1, HP2, HP3)

- **Une seule carte de rendu est LIVRÉE** pour HP1/HP2 (`d3d11drv.dll`, Kentie 1.6.2), et le menu vidéo en propose d'autres : il les énumère d'après les `.int` présents, jamais d'après le `.ini`. HP1 livrait `MeTaLDrv.int` sans sa DLL — le choisir donnait `RenDev` nul, donc « Assertion failed: RenDev [WinViewport.cpp:351] » à CHAQUE lancement suivant. D'où le champ **`display_locked`** (hp1-hp3). **Un `.int` sans sa DLL est une porte ouverte sur un jeu cassé.** Le `fallback` visait `D3DDrv.D3DRenderDevice`, **que ni HP1 ni HP2 ne livrent** (rebalayé : zéro fichier `D3DDrv*`, seuls `.int` = `D3D11Drv`/`IpDrv`/`WinDrv`) — **contrairement à HP3, qui en livre un vrai** (651 264 o, classe `D3DRenderDevice`) et rend par lui sous dgVoodoo. Cette note a longtemps dit « aucun des huit jeux » : c'était faux, et **c'est par jeu qu'il faut vérifier**. **Repli RETIRÉ de hp1 et hp2 au catalogue 0.26** : garder D3D11 laisse une chance, nommer une DLL absente garantit l'échec. Deux facteurs aggravants — `check_d3d11_feature_level` exige le niveau 11_0 alors que le renderer tourne plus bas, et rend `False` hors Windows, si bien qu'au portage Linux TOUT LE MONDE serait parti sur le repli cassé.
- **Le moteur ne lit QUE `GameRenderDevice`.** `WindowedRenderDevice` et `RenderDevice` sont des restes de l'éditeur : HP2 est livré depuis 2002 avec une carte 3dfx que personne n'a, et démarre. Changer de renderer se fait dans le CATALOGUE, jamais dans le `.ini` (les `ini_patches` réimposent `GameRenderDevice` à chaque lancement). **Le portage DX9 du pilote d'UT a été ÉCARTÉ** : il répare les murs que Lumos doit rendre transparents, mais perd ASSAO, SSR, parallax/bump et HDR.
- **Lancer un jeu ne touche PAS ses réglages** : le moteur réécrit le `.ini` utilisateur à la sortie, mais seul `RunCount` change ; `Default.ini` reste intact et HP3 ne réécrit rien. Livrer une configuration réglée dans l'archive sert donc à quelque chose.
- **`Running.ini` est un GARDE-FOU, ne JAMAIS le retirer du catalogue** (hp1/hp2). Sa PRÉSENCE au démarrage ouvre l'assistant « première configuration » (liste de cartes vide, « Commencer ! » passe) ; son ABSENCE déclenche l'autodétection : HP1 se relance lui-même avec `testrendev=D3DDrv.D3DRenderDevice log=Detected.log` (petite fenêtre 410×154), la détection échoue — D3DDrv n'est pas livré — et le moteur **réécrit quand même `GameRenderDevice=D3DDrv` dans `HP.ini`, 0,8 s après l'allumage, à CHAQUE lancement**. La session démarre bien (repli sur D3D11 à l'ouverture de la fenêtre), mais **tout rechargement du rendu en cours de partie relit la config et plante** : Alt+Entrée → `0xC000041D` en 1 s, **2 fois sur 2** ; avec le fichier, même geste, le jeu continue (code 0). Un plantage laisse `Running.ini` sur le disque : le « gain » disparaît dès le premier incident. Mesuré le 2026-09-24 par le chemin exact de `launch_game`, sortie PROPRE (`WM_CLOSE`), `HP.ini` comparé clé par clé — un premier essai de la même nuit concluait « sans danger » parce qu'il tuait le jeu (`Stop-Process`) et ne comparait pas la config. Les `ini_patches` remettent D3D11 avant chaque partie : c'est pourquoi rien ne s'accumule et que le défaut ne se voit qu'EN session. Origine : 2026-03-06, noté « WinDrv v433 crashe s'il est absent », souvenir de Ludo « le jeu réécrit la config à l'allumage ». **Ne JAMAIS passer `StartupFullscreen=True`** : même mécanisme — en plein écran sans le fichier, un Alt+Tab refait `AttemptFullscreen`, relit `D3DDrv` et plante (`Critical Error`, 2/2 ; avec le fichier, non mesuré). HP1 tourne EN FENÊTRE 1920×1080 avec barre de titre. Alt+Entrée persiste `WindowedViewportX/Y` (2560×1440) dans `HP.ini`, avec ou sans le fichier. HP2 non mesuré : même garde, on n'y touche pas.
- **Les DLL ont besoin que `Zone.Identifier` soit retiré**, sinon Windows les bloque et UE1 émet `Can't find file for package` puis assert dans RenDev.
- **Redémarrage de processus** : l'assistant UE1 re-exec un enfant au chargement d'une sauvegarde → `ProcessMonitor` surveille le `Popen` initial **plus** un repli `tasklist` par nom d'exe avec **10 s de grâce**. Ne pas raccourcir.

Les tests de lancement neutralisaient les étapes UNE PAR UNE, par leur nom : une étape ajoutée sans compléter la liste aurait écrit chez la personne qui lance la suite.

## Key Conventions

- Type hints 3.10+ (`str | Path`) ; `pathlib.Path` partout.
- Le travail threadé utilise des `QThread` avec `progress` / `error` + **un signal de fin NOMMÉ** (`download_finished`, `install_finished`, `result`) — jamais `finished`, qui masquerait le natif. Déconnecter symétriquement (try/except `TypeError`) avant de mettre à None.
- Annuler un `QThread` : `cancel()` puis `wait(3000)` avant de relâcher la référence ; au timeout, le garer dans `GameOperations._zombies` et le récolter via `finished`. **Ne jamais laisser un nouveau téléchargement rouvrir un `.part` qu'un vieux thread tient encore** (verrou Windows).
- Tous les callbacks qui mutent l'état vivent sur l'orchestrateur ; les widgets sont des consommateurs bêtes.
- Un slot qui parle à un `QDialog` après sa fermeture possible doit vérifier sa vivacité (patron `_force_update_check` : drapeau + `dlg.destroyed.connect`).
- **Arborescence utilisateur** : `~/Games/AccioLauncher/` ne contient QUE les dossiers de jeux ; tout le reste vit dans `_Launcher/` (`config.json`, `catalog_cache.json`, `sessions.json`, `i18n/`, `trailers/`, `logs/`, `cache/`). Quelqu'un qui ouvre ce dossier veut y voir ses JEUX, et une plomberie visible invite à être supprimée au hasard. **Deux régimes délibérés** : les données du launcher sont à un chemin FIXE (`LAUNCHER_DATA_PATH`) — déplacer ses jeux ne doit pas rendre les journaux introuvables — tandis que le **cache suit `install_path`** (`cache_pour()`), parce qu'une archive de 7 Go doit atterrir sur le même volume que son extraction, sans quoi le rangement devient une copie et la vérification d'espace ment. `migrer_arborescence()` est appelée **avant le logging** (un `RotatingFileHandler` tiendrait le fichier ouvert) **et avant `Config.exists()`** (sinon l'assistant rouvrirait chez quelqu'un qui a huit jeux). Idempotente, n'écrase jamais une destination existante.
- Versions : `0.0.x` bugfix · `0.x.0` jeu ajouté · `x.0.0` tous les jeux livrés. Le numéro vit à TROIS endroits — `pyproject.toml`, `config.APP_VERSION`, badge README — accord tenu par `tests/test_config.py`, et `release.yml` refuse un tag qui ne porte pas `APP_VERSION`.
- `pyproject.toml` fait foi pour les dépendances. **`requires-python = ">=3.12"`** et surtout pas `>=3.10` : `enum.StrEnum` exige 3.11, donc l'ancienne borne laissait pip installer le paquet sur un interpréteur où il plante à l'import.
- **Le jeu de règles ruff est figé** (`select = ["E4","E7","E9","F","W"]`). Sans cette section, « le projet est propre » dépendait du défaut de la version installée : 0.15 → 0.16 a fait apparaître 119 signalements sans qu'une ligne change. `I`/`UP`/`B`/`SIM`/`C4`/`RET` sont des adoptions candidates, à traiter en une passe dédiée.
- Thème sombre (`#060611`, or `#d6a72c`). Tout nouveau stylesheet contenant un hex or OU une surface bleu nuit doit passer par `theme.themed(...)` ; tout `QColor` or dans un paintEvent par `accent_qcolor(alpha)`, tout voile sombre par `bg_qcolor(alpha)`.
- **Ko-fi sans nag** : exactement UN remerciement dans la vie du launcher (`kofi_milestone_thanked`, cap **2 h**, `_KOFI_CAP_SECONDES`). Le cap était à 10 h : le remerciement n'existant qu'une fois, le placer si loin revenait à ne l'adresser à presque personne. **La règle « une seule fois » ne bouge pas.**
- Hero dynamique : la vue ouvre sur `manager.last_played_game_id()` via `carousel.select(idx)` — ne pas appeler `set_game` directement pour un index ≠ 0.
- Nav clavier : ←/→ routés par `MainWindow._handle_global_key` ; ne pas ajouter de `keyPressEvent` aux widgets pour ça. Les widgets d'édition gardent leurs flèches.

## Don't reintroduce these

129 règles, chacune payée une fois. Groupées par sujet ; l'ordre dans un groupe n'a pas de sens.

### Processus, threads, sortie

1. **Lancer un programme par son seul nom** (`["tasklist", …]`, `["cmd", "/c", …]`) — `CreateProcess` le cherche d'abord dans le dossier de l'exe APPELANT, souvent Téléchargements, où un `tasklist.exe` déposé serait exécuté à chaque partie. Passer par `win_utils.commande_systeme("tasklist.exe")` ; dans un `.bat`, par `%ACCIO_SYS%`. Filet : `tests/test_securite.py` (AST).
2. **Faire taire Bandit sans relire** — la CI échoue au moindre signalement. Deux règles seulement sont écartées dans `.bandit` (B311, B404). Tout autre appel porte `# nosec B603` SUR SA LIGNE, raison sur la ligne du DESSUS (Bandit lit les mots qui suivent `nosec` comme des noms de règles).
3. **`terminate()` sur un QThread Python DANS le processus de pytest** — le thread tué laisse sa pile inscrite dans l'interpréteur. CI rouge : violation d'accès dans `_peindre_discord`, avec au faulthandler le thread mort de `test_fermeture_threads.py`. Tout test qui atteint `terminate()` tourne en SOUS-PROCESSUS.
4. **Jeter le résultat d'un `wait()` sur un `QThread` à la fermeture** — s'il n'a pas fini il reste enfant, Qt le détruit vivant : abandon du processus, `0xC0000409`, aucun message (abandon C++, `install_excepthook` ne le voit pas). Passer par `arreter_a_la_fermeture`. **`window.close()` ne détruit rien** tant que `WA_DeleteOnClose` n'est pas posé, donc une sonde qui s'arrête là conclut à tort.
5. **Importer un module d'extension Qt (`QtNetwork`, `QtMultimedia`, `QtSql`…) depuis une FONCTION** — créer un module C pendant que le GC peut passer sur des objets Qt vivants donne un « access violation » **aléatoire**. `QtCore`/`QtGui`/`QtWidgets` ne sont PAS concernés (déjà chargés). `video_player` créait `QtMultimedia` **au premier trailer, chez l'utilisateur** ; remonté en tête de module pour +6 ms, `MULTIMEDIA_DISPONIBLE` conservant la dégradation gracieuse. Filet AST : `tests/test_imports_qt.py`.
6. **Nommer une constante `subprocess.CREATE_*` ailleurs qu'à l'import, sous garde** — elles n'existent que sous Windows, et l'`AttributeError` tombe AVANT `Popen` : la fonction devient intestable hors Windows. Voir `self_update._DRAPEAUX_DETACHE`.
7. **`finished = pyqtSignal(...)` sur un QThread** — masque le natif ; nommer `*_finished` (tests `test_finished_not_shadowed`).
8. **Brancher un signal Qt directement sur une méthode de `GameManager`** — `__slots__` sans `__weakref__`, et PyQt garde une référence FAIBLE : `SystemError`. Rien n'échoue à l'import ni en test unitaire, seulement au premier câblage réel. Relayer par un slot de l'objet Qt. pyqt-pitfalls #46.
9. **Ajouter un argument à un signal sans mettre à jour TOUS ses slots** — PyQt tronque en silence. L'empreinte SHA-256 de l'auto-update était ainsi jetée sur le chemin « Vérifier les mises à jour », qui installait donc un exe non vérifié pendant que la vérification au démarrage, elle, le vérifiait. Filet : `TestAriteDesSlots`.
10. **Appeler une `@property` comme une méthode** — `self._speed_tracker.speed()` levait `TypeError` à CHAQUE fin de téléchargement réussi, donc AVANT `install()` : plus aucun jeu ne pouvait s'installer. Passé une journée et un exe publié sans être vu, parce que `GameOperations` était le SEUL module sans test. Tout nouveau chemin de cet orchestrateur vient avec le sien.
11. **Un objet Qt durable créé sans parent** (`QPropertyAnimation(cible, b"prop")`, `QMenu()`) — il n'appartient qu'à Python, survit au widget qu'il sert et meurt quand le GC passe, à un instant quelconque, y compris pendant qu'une autre fenêtre se peint. Sept cas corrigés. Côté tests, `conftest._widgets_detruits_a_la_fin_du_test` les détruit à la fin de CHAQUE test **et les TIENT jusque-là** : pytest-qt ne garde qu'une référence FAIBLE et fait tourner la boucle APRÈS la fin du test, et le GC détruisait une fenêtre au milieu de son propre dessin. Filet : `tests/test_objets_qt_parentes.py`. Aucun test ne parle au vrai client Discord (`_jamais_le_vrai_discord`).
12. **Monkeypatcher un attribut de CLASSE Qt dans un test** — remplacer puis « restaurer » `ParticleOverlay.update` laisse le descripteur sip posté en attribut Python, et le process meurt plusieurs FICHIERS plus loin. Vaut aussi pour une `property` posée sur un `QObject`. Chaque fichier passe seul, et `-v` masque le défaut en ralentissant. **Deux leçons d'outillage** : un site de plantage qui CHANGE d'une exécution à l'autre désigne un état corrompu et jamais le code qui peint ; la seule méthode qui tranche est la bissection par fichier. Espionner par une sous-classe, ou poser le faux sur l'INSTANCE.

Payé sur `faits_du_jour`, découvert par un test du RÉGLAGE, pas de la config. **Troisième occurrence de « deux listes qu'aucun calcul ne relie ».** Filet : `TestChaqueReglageEstReellementPersiste`.

La décision se prend **une seule fois**, avant la reconstruction (`selected_id=`).
102. **Armer un `QTimer.singleShot` pour un démarrage différé** — il ne s'annule pas et ne se **réarme** pas, deux défauts distincts payés le même jour. ① `_stop_video()` laissait le minuteur en vol, le trailer repartait **sans image** après que la fenêtre soit partie au tray. Sans téléchargement on s'attarde, le minuteur a déjà tiré, et le défaut ne se reproduit pas — d'où « ça marche pourtant d'habitude », **signe d'une COURSE et non d'un cas rare**. ② Chaque changement de jeu en armait un de plus, et le garde-fou comparait le jeu AFFICHÉ au jeu ATTENDU, deux valeurs toujours d'accord une fois la rafale finie. Remède : minuteur **possédé** (`setSingleShot`) — `start()` repart de zéro, `stop()` annule. La condition reste en second garde-fou, `isVisible()` en troisième.

Même fonction de copie que l'installation, donc mêmes gardes.

### Ce que l'interface a le droit de dire

107. **Afficher un état NORMAL** (« espace libre : 412 Go », pastille « en ligne », « prérequis OK ») — un état ne s'affiche que lorsqu'il **DÉVIE** ; sinon c'est du bruit qu'on apprend à ignorer, et le vrai avertissement se noie avec.
108. **Affirmer un résultat qu'on n'a pas obtenu** — « Vérifier les mises à jour » hors ligne répondait « Catalogue déjà à jour ». L'absence de signal est INDISTINGUABLE d'un catalogue à jour : les deux rendaient la même chaîne. C'est le pendant du faux « hors ligne », et mentir dans ce sens n'est pas moins grave. Même faute côté jeu : un lancement mort en 0,5 s recevait « Bon jeu ! » alors qu'`add_playtime` venait de le classer en TENTATIVE. **Quand le launcher ne sait pas, il le dit ; quand il sait, il ne se tait pas.**
109. **Déclarer « hors ligne » sur une erreur HTTP** — un 403 ou un 404 prouvent que la connexion marche. Seules les erreurs de TRANSPORT comptent, et une seule réponse annule le verdict.
110. **Laisser l'état hors-ligne sans re-tentative** — `_offline_retry` (45 s, ré-armé à CHAQUE échec, arrêté dans `closeEvent`) ; sans lui, rebrancher son câble laisserait « Télécharger » grisé jusqu'au prochain démarrage.
111. **Une boîte d'échec qui accuse la connexion sans le savoir** — le téléchargement disait « Vérifiez votre connexion » quelle que soit la cause, disque plein et antivirus compris. La cause vient d'`echecs.cause_de` sur la DERNIÈRE exception. Une nouvelle erreur doit être une sous-classe d'`OSError` (sinon la boucle de reprise ne la voit pas) et avoir sa cause.
112. **Annoncer un échec de téléchargement sans dire ce qui est CONSERVÉ** — câble coupé à 60 %, le `.part` garde ses octets et la requête suivante repart en `Range`, mais le seul mot affiché était « Échec ». Sur 4,6 Go, c'est quelqu'un qui a déjà attendu vingt minutes et qui renonce alors qu'il ne lui manque rien.
113. **Proposer une mise à jour du launcher sans dire ce qu'elle CONTIENT** — on demandait d'accepter le remplacement d'un exécutable sur la seule foi d'un numéro, **alors que le launcher affiche le changelog de chaque version de JEU** : il se tenait à une exigence plus basse que ce qu'il distribue. Le texte est **déjà téléchargé** (même réponse GitHub), il était simplement jeté. Pas de notes → pas d'en-tête « Nouveautés » vide.
114. **Effacer tout seul une notification qui demande une action** — le bandeau disparaissait après 30 s. Il reste jusqu'à ce que l'utilisateur tranche ; la croix écarte pour de bon. La proposition est en plus un **vrai dialogue**, posé UNE fois par session — c'est une question, pas une information.
115. **Transformer un modal de QUESTION ou d'ERREUR en toast** — un toast qui disparaît emporterait une erreur que l'utilisateur doit lire.
116. **`QMessageBox.StandardButton.Yes` / `.No`, et les raccourcis `question()` / `warning()` / `information()`** — ces libellés viennent des `qtbase_<langue>.qm` que `_keep()` écarte du build : un launcher en français affichait **« Yes » et « No »**. Deux systèmes de traduction pour une même fenêtre, dont un que `test_i18n.py` ne voit pas et qu'un bénévole ne peut pas atteindre. Les raccourcis laissent en plus le texte en `AutoText` alors qu'il interpole des noms de jeu. Passer par `_boite` ou `avertir`. **Un bouton nommé vaut mieux qu'un « Oui »** : « Désinstaller » répond à la question tout seul. Le filet doit rester un balayage AST, le dépôt CITANT ces noms pour expliquer qu'il ne les emploie plus.
117. **Empiler plusieurs avertissements dans le bandeau** — 80 px, soit le retour de la scrollbar à 980×660, pour un second conseil même pas actionnable.
118. **Poser un réglage sans rien qui dise qu'il en est un** — la langue du jeu n'existait que comme segment doré de la ligne méta. **Un réglage qu'il faut deviner n'existe pas.** L'engrenage ouvre `GameSettingsDialog` — une FENÊTRE et non un menu, les réglages d'un jeu allant s'étoffer. La rubrique « Affichage » y est **verrouillée et nommée** : qui cherche la résolution doit comprendre que ce n'est pas lui qui n'a pas trouvé. Pas de bouton « Appliquer » : une invite UAC se comprend juste après un clic sur une langue, pas après un « Appliquer » qui regrouperait trois réglages. Un choix refusé remet le bouton radio sur ce que porte VRAIMENT le registre.
119. **Un bloc qui a l'air d'un bouton et ne répond pas** — tout ce qui est encadré, coloré et aligné comme une rangée de boutons doit se cliquer, se survoler et s'atteindre au clavier (←/→/Début/Fin/Espace), anneau DESSINÉ.
120. **Un seuil d'affichage sur le compteur de téléchargements** — écarté : « je veux les vrais chiffres ». `_DL_COUNT_MIN` valait 1, donc ne masquait déjà rien ; c'est le PLAN de le monter à ~100 qui est abandonné. Le `count > 0` restant n'est pas un seuil mais une honnêteté.
121. **Remettre une durée estimée sur le bouton TÉLÉCHARGER** — calculée sur la vitesse du DERNIER téléchargement, qui n'a aucune raison de valoir encore, et allongeait le libellé jusqu'au débordement. `estimate_duration` et `format_duree` ont été retirés avec elle : **pas de code mort en réserve.**
122. **Confondre une DURÉE et un TEMPS RESTANT** — « ≈ ~19s restantes » sur un bouton : deux marqueurs d'approximation empilés, et un « restantes » qui parle d'un téléchargement pas encore lancé.
123. **Figer le statut du démarrage dans une image** — un écran de chargement qui n'affiche pas où en est le chargement ne sert à rien.
124. **Revenir à `QSplashScreen`** — son `show()` coûte ≈ 1 s là où une `QWidget` aux mêmes drapeaux prend 2 à 19 ms, et c'est la seconde qui précède le premier pixel. Le dessin est le même (0 écart sur 275 100). Filet : `TestLeSplashNeCoutePasUneSeconde`.
125. **Traiter le choix « je veux les bandes-annonces » comme une réponse jetable** — persisté dans `trailers_optin`, sinon une coupure laisse trois vidéos sur huit, définitivement, sans que rien à l'écran ne relie l'une à l'autre.

126. **Télécharger en arrière-plan sans que rien à l'écran ne le dise** — les bandes-annonces partaient à l'acceptation et n'apparaissaient QUE dans les Paramètres : plusieurs centaines de Mo sans trace visible. « On s'attend à la voir quelque part facilement et pas caché, ou alors prévenir que le téléchargement est en fond. » Les deux, désormais : un toast au départ, et la progression dans la barre de statut (qui ne coûte aucun pixel et cède devant un téléchargement de jeu). Le contrat du magasin ne bouge pas — **il émet, la fenêtre affiche** ; ce qui était en trop, c'est le silence.

### Produit : ce qui a été tranché

127. **Poser un DESSIN dans un coin de la fiche** — cinq silhouettes peintes ont vécu quelques heures en bas à droite. Verdict le jour même : « vraiment pas beau… ça surcharge l'écran ». **Retirées, module et tests supprimés.** La leçon n'est pas que le tracé était raté : **la fiche porte déjà une illustration pleine page, qui EST le visuel du jeu**, et le coin bas-droit est le seul espace encore calme. L'Almanach habille par les PARTICULES et le fait du jour, qui n'occupent aucune surface. Ne pas reproposer de décor peint, d'asset téléchargé ni de filigrane sans demande explicite.
128. **Une ambiance de l'Almanach qui ne dure qu'un JOUR** — « pour les events, laisse le mois complet ». Une ambiance vue un jour par an n'existe pas, et qui la manque n'a aucun moyen de savoir qu'elle a existé. **Le JOUR reste ce qui compte pour le fait du jour.** Corollaire : un test qui suppose l'ambiance par défaut échoue cinq mois sur douze — **poser l'ambiance EXPLICITEMENT**.
129. **Dire qu'une année « attend » alors qu'elle est DERRIÈRE** — « Tu es en 7ᵉ année. La 4ᵉ année t'attend. » « Attendre » décrit ce qui vient ensuite ; une année sautée ne vient pas ensuite, elle manque. `prochaine_annee` regarde depuis OÙ L'ON EST ; quand il n'y a plus rien devant, on compte ce qui reste.

**Deux règles transversales**, déjà citées ci-dessus mais qui reviennent partout :

- **Déduire le SENS d'un jeu de son RANG dans le catalogue** — le catalogue est une liste ordonnée par commodité, pas une structure de données. Tout ce qui a un sens se DÉCLARE (`annee`) ; un jeu qui ne déclare rien tombe hors du classement au lieu de le décaler. Filet : `TestLeQuidditchNeCasseRien`, qui pose le jeu hors programme AU MILIEU du catalogue.
- **Laisser un bloc grossir dans un fichier hôte parce qu'il « va avec »** — le critère n'est PAS la taille, c'est qu'aucun de ces blocs ne touchait les objets de son hôte. Le symptôme partagé est plus parlant que la métrique : **quatre des cinq blocs extraits n'avaient aucun test**, parce que les exercer supposait de construire la fenêtre entière. **Ce qui est noyé n'est pas testé, et ça ne se voit pas dans un compte de lignes.** Corollaire d'outillage : quand une extraction est propre, **les imports devenus inutiles le disent** ; si rien ne se libère, la frontière n'était pas là.

### Pièges de test récurrents

- **Un test de mise en page avec un `qtbot.wait(n)` fixe** — la remontée du panneau passe par une chaîne de `singleShot(0)` qui se réarme : 80 ms suffisent à vide et pas toujours sous charge. Or `build.bat` s'arrête au premier échec : **un test qui rate une fois sur dix est pire qu'une absence de test** — on apprend à le relancer sans le lire. `qtbot.waitUntil(…, timeout=3000)`.
- **Un test qui n'appelle que `pixmap_icone` sans demander `qtbot`** — rien ne fait naître la `QApplication`, or `QPixmap` en exige une : `qFatal`, processus **ABANDONNÉ**, sans trace ni sortie pytest. Invisible en jouant le FICHIER entier ; n'apparaît qu'en jouant la classe SEULE, c'est-à-dire quand on la débogue. Symptôme : code de sortie étrange (127 en bash, 3221226505) **et aucune ligne de sortie**.
- **Émettre un signal d'UI sur une VRAIE fenêtre sans regarder où il est câblé** — `versions_clicked` ouvre un dialogue dont l'`exec()` bloque indéfiniment. Tester l'aiguillage sur un widget isolé.
- **Attendre un fichier écrit par un autre processus en testant son existence** — sous Windows, `marker.exists()` devient vrai quand `cmd` OUVRE le fichier pour `>`, **avant** que l'`echo` n'y dépose quoi que ce soit, et la lecture peut échouer franchement (partage refusé) tant que le handle est tenu. Attendre un contenu NON VIDE, avec `except OSError`. Voir `_attendre_contenu` dans `tests/test_self_update.py`.
