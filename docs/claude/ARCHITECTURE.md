### Journal, sortie et CI

**`main.py`** configure le logging rotatif, l'exception de haut niveau, `install_excepthook()` et le splash avant `MainWindow`. Fichier en **INFO dans l'exe**, DEBUG depuis les sources, `ACCIO_JOURNAL=debug` pour rendre le détail à l'exe. Sous Linux : `assainir_environnement()` avant `QApplication`, et **`setDesktopFileName(DESKTOP_ID)`** (`be.acciolauncher.AccioLauncher`) — l'équivalent de l'AppUserModelID : sous Wayland, `setWindowIcon` est ignoré, c'est cet `app_id` qui relie la fenêtre à son `.desktop`, donc à son icône.

**`main()` sort par `os._exit(code)` après `logging.shutdown()`**, jamais par `sys.exit(app.exec())` : pendant la finalisation de l'interpréteur, sip détruisait les objets C++ dans le désordre — violation d'accès dans `sip.cp314-win_amd64.pyd` à **2 fermetures sur 8**, et 5 fois au journal Windows ; **0 sur 14** après. `PyQt6.sip` n'a plus `setdestroyonexit`. Tout ce qui doit être écrit l'est dans `closeEvent`.

**Paquets CI figés avec empreintes** (`.github/requirements/*.txt`, `--require-hashes`) : un `tests.txt` résolu en `--universal` couvre Windows 3.12/3.14 et Linux ; `build.bat` n'en dépend pas. **CodeQL** tourne en workflow (Scorecard ne reconnaît pas le « default setup », ni Bandit, comme SAST ; les deux ne peuvent coexister). **Fuzzing** (`fuzz.yml`, Atheris, Linux) : `fuzz/invariants.py` écrit en assertions ce que promettent les barrières entre le catalogue DISTANT et la machine ; `tests/test_fuzz.py` les rejoue sous Windows. Il a trouvé `"year": 1e999`, les séparateurs de ligne Unicode dans un `.reg`, et des noms d'archive que les deux gardes Zip Slip jugeaient différemment.

**`tests.yml`** — pytest sur `windows-latest` en **3.12 ET 3.14** (3.12 est le plancher déclaré et n'avait jamais été testé : `Path.read_text(newline=…)`, apparu en 3.13, y cassait `tools/sync_trailers.py`) + smoke `ubuntu-24.04` offscreen, **bloquant**. Ce job fut rouge à CHAQUE run depuis sa création : ne bloquant rien, personne ne le regardait. Remis au vert, **puis rouge de nouveau quatre semaines** pour la même raison — 25 tests de LANGUE DE JEU supposaient un registre Windows sans le dire. Remède : la fixture **`registre_atteignable`**, à demander pour tout nouveau test de langue de jeu. **Tant qu'un job n'est pas bloquant, un rouge y dure des semaines. Ne pas remettre `continue-on-error`.** Pour reproduire : `python:3.14-slim` + les bibliothèques Qt du workflow **+ `libgssapi-krb5-2`** (QtNetwork la réclame) **+ `fontconfig fonts-dejavu-core fonts-liberation`** — sans le paquet `fontconfig`, la bibliothèque est là mais ne trouve aucune police, ce qui fait un troisième environnement. **+ `libglib2.0-0t64`** (le runner Ubuntu l'a d'office, pas l'image : `conftest` s'arrête sur `libglib-2.0.so.0`), et **lancer pytest sous un utilisateur NORMAL** (`useradd`, `su`) : en root, un fichier en lecture seule reste inscriptible et `test_l_attribut_de_l_archive_est_conserve` échoue pour rien. Rouge du 2026-09-27 (cinq commits) : un test de captures attendait le chemin de l'hôte là où Linux écrit `Z:\…` — **un test qui écrit un chemin pour le JEU passe par `chemin_pour_le_jeu`**.

**Releases construites par la CI** (`release.yml`). **Tout se fait depuis le site GitHub** : Actions → release → Run workflow, case « Créer la release » cochée. Le tag se DÉDUIT d'`APP_VERSION` (refus hors de `main` ou si la version a déjà un tag) et naît sur le commit construit (`--target`) — **pas de déclenchement sur tag**, publier le brouillon en créant un relancerait un build voué à l'échec. **Trois jobs** : `version` (le tag, calculé UNE fois), `windows` (`build.bat`) et `linux` (`build.sh`, **`ubuntu-22.04`** : une AppImage exige la glibc de sa machine de build ; tous les autres jobs Linux des workflows sont figés en `ubuntu-24.04`, jamais `ubuntu-latest`, qui passe à Ubuntu 26 le 2026-10-19) en parallèle, puis `brouillon`, qui n'existe que si les DEUX ont réussi — tout ou rien. Attestation de provenance Sigstore sur CHAQUE binaire (et son `.sigstore.json` joint), UNE release en **BROUILLON** portant les quatre fichiers, notes pré-remplies depuis `.github/release-notes.md`. Rien n'est public avant « Publish release », et l'auto-update ne voit pas un brouillon. Case décochée = build d'essai. `build.bat` le permet par `CI` et `ACCIO_PY`. **Toutes les actions épinglées par empreinte de commit**, Dependabot tient les deux à jour. `LICENSE` ne contient QUE le texte GPL v3 officiel (sinon GitHub affiche « Other ») : les termes additionnels de l'article 7 vivent dans `ADDITIONAL-TERMS.md`. **Licence : GPL-3.0-only depuis le 2026-09-24** (MIT jusqu'à la 1.0.6) — la plus stricte que permet PyQt6 ; interdire la redistribution exigerait PySide6 ou une licence Riverbank.

**AppImage** (`build/linux/`). Le spec produit un DOSSIER sous Linux (onedir : un onefile dans une AppImage se décompresserait en plus dans /tmp à chaque démarrage), que `appimage.py` range dans `AccioLauncher.AppDir` (`usr/lib/AccioLauncher`, `AppRun` en sh, `.desktop`, icônes EXTRAITES telles quelles des sept tailles de l'`.ico`, licence et avis tiers dans `usr/share/doc`). **appimagetool 1.9.1 et le runtime `type2-runtime` 20251108 sont épinglés par version ET empreinte** (jamais `continuous`) ; le runtime est statique, donc **pas de libfuse2** requise — absente de Fedora, donc de Bazzite. **Le nom ne porte pas la version** (`AccioLauncher-x86_64.AppImage`) : l'auto-mise à jour remplace le fichier sur place, et `updater.asset_de_la_plateforme` le reconnaît à son architecture. Relevés sous Xvfb sur l'AppImage elle-même : `WM_CLASS` = `AccioLauncher` (d'où `StartupWMClass`), journal « (AppImage) », et le chargeur PyInstaller onedir place `_internal` en tête de `LD_LIBRARY_PATH` sans créer `LD_LIBRARY_PATH_ORIG` s'il n'y avait rien — les deux cas de `compat.environnement_hote`, vérifiés sur un enfant réel. 62 Mo (l'exe : 42), **grâce à `strip=True` sous Linux** : le Python d'`actions/setup-python` garde ses symboles de débogage (`libpython` : 33 Mo, 7 épurée), et le build d'essai de la release sortait 77 Mo là où le poste en faisait 62 — le contenu d'un build ne dépend pas de la machine qui le fait (règle 94).
